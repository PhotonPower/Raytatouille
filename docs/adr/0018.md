# ADR 0018: Python-Build-Abhängigkeiten über pyproject.toml statt vcpkg

**Status:** angenommen (2026-10-04)

## Kontext

AGENTS.md Regel 4 lässt neue Abhängigkeiten nur über `vcpkg.json` zu. Für das Python-Paket
`raytatouille` (#32, ADR 0002) braucht der Build nanobind und scikit-build-core, die Tests numpy,
pytest und mypy. Der vcpkg-Port `nanobind` (2.13.0 an unserer Baseline) hängt am Port `python3`:
vcpkg baut dafür CPython 3.12 aus den Quellen (ungecacht etwa 10 Minuten je OS und Preset). Die
Erweiterung würde dann gegen die Header und unter Windows gegen die Importbibliothek dieser
vcpkg-Python gebaut statt gegen den Interpreter, der pytest und numpy ausführt. Das legt das
Projekt auf eine Python-Version fest, und `FindPython` kann die falsche Python finden. Der
Koordinator hat im Auftrag des Maintainers in #32 entschieden.

## Entscheidung

1. **Ausnahme von Regel 4 nur für reine Python-Build- und Testwerkzeuge:** nanobind,
   scikit-build-core, numpy, pytest und mypy kommen aus PyPI. Build-Abhängigkeiten stehen in
   `pyproject.toml` (`build-system.requires`), alle zusammen gepinnt in
   `libs/rtt-py/tests/requirements.txt`. Neue Werkzeuge dieser Art brauchen dieselbe
   Lizenzprüfung wie vcpkg-Abhängigkeiten (ADR 0010) und einen Eintrag in diesem ADR.
2. **C++-Bibliotheken** (Eigen, nlohmann-json, oneTBB, Catch2, ...) kommen weiterhin nur über
   vcpkg; die Ausnahme gilt nicht für sie.
3. **Python** ist der Interpreter, der baut: CMake findet nanobind über
   `python -m nanobind --cmake_dir` dieses Interpreters (`libs/rtt-py/CMakeLists.txt`).

## Lizenzprüfung (ADR 0010)

Geprüft an den installierten Paketen (`*.dist-info`, Lizenztexte im Paket) am 04.10.2026:

| Paket | Version | Lizenz | Rolle |
| --- | --- | --- | --- |
| nanobind | 2.13.0 | BSD-3-Clause | Build; Code wird in `_core` gelinkt |
| robin-map (in nanobind, `ext/robin_map`) | wie nanobind | MIT | Build; Code wird in `_core` gelinkt |
| scikit-build-core | 1.1.1 | Apache-2.0 | Build-Backend, nicht im Paket |
| numpy | 2.2.6 (Python 3.10), 2.5.3 | BSD-3-Clause AND 0BSD AND MIT AND Zlib AND CC0-1.0 | Laufzeit (Arrays), vom Nutzer installiert |
| pytest | 9.1.1 | MIT | nur Tests |
| mypy | 2.4.0 | MIT | nur Tests |

Alle sind mit MIT verträglich. nanobind und robin-map landen als Code in der Erweiterung; ein
späteres Binärpaket (Wheel auf PyPI) muss ihre Lizenztexte mitliefern (BSD-3, Klausel 2), ebenso
die der C++-Abhängigkeiten im Wheel: oneTBB (Apache-2.0; unter Windows `tbb12.dll`, unter Linux
statisch gelinkt), nlohmann-json (MIT) und Eigen (MPL-2.0).

## Verworfen

- **vcpkg-Port nanobind:** baut CPython aus den Quellen, legt auf Python 3.12 fest und riskiert
  die falsche Python bei `FindPython` (siehe Kontext).
- **nanobind als Git-Submodul:** Version und Lizenzprüfung wären an einem dritten Ort.

## Folgen

- Der Python-Build braucht `pip install -r libs/rtt-py/tests/requirements.txt` vor CMake.
- Die C++-Presets sind unverändert; nur `ci-linux-python` und `ci-windows-python` bauen das
  Paket (`RTT_BUILD_PYTHON=ON`).
- AGENTS.md Regel 4 verweist auf dieses ADR.

## Nachtrag (#33): matplotlib

`raytatouille.plot` (#33) zeichnet Analyseergebnisse mit matplotlib. matplotlib ist eine
optionale Laufzeitabhängigkeit (Paket-Extra `raytatouille[plot]`, Import erst in den
Plotfunktionen) und für die Tests in `libs/rtt-py/tests/requirements.txt` gepinnt: 3.10.9 für
Python 3.10, 3.11.2 ab Python 3.11 (matplotlib 3.11 verlangt Python ≥ 3.11). Der Koordinator hat
das in #33 entschieden.

| Paket | Version | Lizenz | Rolle |
| --- | --- | --- | --- |
| matplotlib | 3.10.9 / 3.11.2 | Matplotlib License (PSF-basiert, Klassifikator „Python Software Foundation License“), BSD-kompatibel | optional zur Laufzeit (Plots) und in den Tests, vom Nutzer installiert, nicht im Wheel |

Geprüft am installierten Paket 3.11.2 (`*.dist-info`, Lizenztext und Klassifikator) am
04.10.2026. Das matplotlib-Wheel bringt eigene Bestandteile mit (u. a. FreeType unter
„FTL OR GPL-2.0-or-later“, Qhull, Schriften unter OFL-1.1); da `raytatouille` matplotlib weder
linkt noch mitliefert, betrifft das nur die Weitergabe von matplotlib selbst. Die
Abhängigkeiten von matplotlib (contourpy, cycler, fonttools, kiwisolver, pillow, pyparsing,
python-dateutil, packaging) installiert pip mit; auch sie landen nicht im Wheel von
`raytatouille`.
