# ADR 0042: Anamorphe Flächen und Paraxialrechnung je Schnitt (M8 S2)

**Status:** vorgeschlagen

## Kontext

S2 (#315) bringt die anamorphen Flächentypen v1: Biconic, Toroid und Zylinder (`docs/architecture.md`, Abschnitt Geometrie). Der Vorschlag steht auf #315 (Kommentar vom 2026-11-05); der Maintainer hat allen Empfehlungen F1 bis F5 zugestimmt.

ADR 0041 legt die Grundlagen fest:

- Jede Form liefert ihre Scheitelentwicklung (Punkt 1).
- Die rotationssymmetrische Paraxialrechnung lehnt ungleiche Diagonalen der Hesseschen ab (Punkt 2, Tabelle).
- Bis zu einer API je Achse aus S2 werfen Zielung und alle Analysen, die sie brauchen, ohne Bezug eines Nennsystems (Punkt 3).
- Die API je Achse muss die Hessesche mit der Drehung um z transformieren (Punkt 2, „Anamorphe Rechnung“).

Bestandsaufnahme (main 26d4253):

- **Zielung:** `make_context_core` (`rtt-trace/src/sources.cpp`) ruft `first_order`. Ein Fehler dort ist fatal, auch für die reale Zielung, die den paraxialen Strahl nur als Startwert nutzt. Ohne Paraxialdaten zielt nur `AimReference` (ADR 0007, Nachträge #252, #255) mit den Daten eines Nennsystems.
- **Weitere Nutzer von `first_order`** (Feldkurven, Farbfehler, Geister, Austrittspupille für OPD, Operanden): werfen oder melden `merit.operand_unsupported`; der Maßreport fängt den Fehler ab.
- **Schnitt:** `intersect_newton` prüft das Gebiet einer Form nur über `max_radius()`, also als Kreis um den Scheitel. Das Gebiet eines Biconic ist eine Ellipse, das eines Toroids und eines Zylinders kein Kreis.
- **Ideale Zylinderlinse** (ADR 0031, Punkt 6): `first_order` lehnt sie ab; sie ist das bestehende anamorphe Element.

## Entscheidung

### 1. Formen

Quelle: Ansys Zemax OpticStudio User Guide, Release 2025 R1, Seiten „Biconic“ und „Toroidal“ (Zeilen in `docs/quellen.md`). Die Gleichungen dort sind Bilder ohne Nummer.

Alle drei Typen gelten im lokalen System der Fläche, wie `conic`. Die Richtung ihrer Schnitte legt die Drehung der Fläche um z fest.

**Biconic** (`biconic`), Parameter `radius_x`, `radius_y`, `conic_x`, `conic_y` (Param):

- z = N / (1 + S), mit N = c_x x² + c_y y², S = √(1 − a x² − b y²), a = (1 + k_x) c_x², b = (1 + k_y) c_y², c_x = 1/R_x, c_y = 1/R_y. Das ist die Formel der Quelle.
- Gradient, durch Ableiten hergeleitet:
  - ∂z/∂x = 2 c_x x / (1 + S) + a x N / (S (1 + S)²), ∂z/∂y entsprechend mit c_y und b.
  - Für c_x = c_y und k_x = k_y wird daraus c x / S, die Ableitung der Konik (mit 1 − S² = (1 + k) c² r²).
- Beide Radien sind endlich und ≠ 0, geprüft mit `shape.radius_invalid` wie bei `conic`. Asphärenterme gibt es nicht, wie in der Quelle.

**Toroid** (`toroid`), Parameter `radius` (y-z-Profil), `conic`, `coefficients` (A4, A6, …) und `radius_of_rotation` (Param):

- **Profil** in der y-z-Ebene: z_y(y) = c y² / (1 + √(1 − (1 + k) c² y²)) + Σ_{i≥2} A_{2i} y^{2i}, mit c = 1/`radius`.
  - Die Quelle hat dazu einen Term α₁ y²; ohne ihn bleibt die Scheitelkrümmung im y-Schnitt c (Entscheidung F2).
  - Der ZMX-Import (I1) lehnt α₁ ≠ 0 ab.
- **Drehung:** Das Profil dreht sich um die Achse parallel zu y durch (x, z) = (0, R), R = `radius_of_rotation` mit Vorzeichen. Die Quelle gibt die Fläche dafür nur in Worten an. Herleitung:
  - Ein Profilpunkt hat von der Achse den Abstand |d| mit d = R − z_y(y). Gedreht gilt x² + (z − R)² = d². Der Ast durch den Scheitel ist z = R − sign(d) √(d² − x²).
  - Umgeformt ohne Auslöschung: **z = z_y + c′ x² / (1 + √(1 − c′² x²))**, mit c′ = 1/d = c_R / (1 − c_R z_y) und c_R = 1/R. Denn R − sign(d) √(d² − x²) = z_y + d (1 − √(1 − x²/d²)) = z_y + d · (x²/d²) / (1 + √(1 − x²/d²)).
- **Gradient:** ∂z/∂x = c′ x / √(1 − c′² x²) und ∂z/∂y = z_y′(y) / √(1 − c′² x²).
  - Die zweite Formel folgt aus ∂z/∂d = −1/√(1 − x²/d²) und ∂d/∂y = −z_y′.
  - z_y′(y) = c y / √(1 − (1 + k) c² y²) + Σ 2i A_{2i} y^{2i−1}.
- Beide Radien sind endlich und ≠ 0.

**Zylinder** (`cylinder`), Parameter `radius`, `conic`, `coefficients` (Entscheidung F1):

- z = z_y(y), das Profil des Toroids ohne Drehung, also flach in x. Das ist der Grenzfall c_R = 0 der Toroidformel.
- Gradient: (0, z_y′(y)).
- Toroid und Zylinder teilen den Code des Profils.

**Gebiet** (Erweiterung von `IntersectableShape`, ADR 0041, Punkt 4):

- **Neues optionales Element** `in_domain(x, y) noexcept -> bool`.
  - `intersect_newton` nutzt es, wenn die Form es hat (`if constexpr`); sonst gilt wie bisher der Kreis aus `max_radius()`.
  - Plane, Conic und EvenAsphere bekommen es nicht. Ihr Schnitt bleibt so bitgleich.
- **`max_radius()`** heißt künftig ausdrücklich: Radius der größten Kreisscheibe um den Scheitel, die ganz im Gebiet liegt. Für die bestehenden Typen ist das ihr heutiger Wert. Die Startebene der Zielung und die Profilkurven des Layouts nutzen ihn. Dass er bei nicht runden Gebieten kleiner ist als das Gebiet, ist dort konservativ.
- **Biconic:**
  - Gebiet a x² + b y² ≤ 1.
  - `max_radius` = 1/√max(a, b), wenn max(a, b) > 0, sonst unbegrenzt.
- **Zylinder:**
  - Gebiet (1 + k) c² y² ≤ 1.
  - `max_radius` wie bei `conic`: 1/(|c| √(1 + k)) für k > −1, sonst unbegrenzt.
- **Toroid:**
  - Gebiet: das Profil wie beim Zylinder, dazu sign(R) d > 0 (das Profil kreuzt die Drehachse nicht) und |x| ≤ |d|.
  - `max_radius` ist das größte r unter der Profilgrenze mit m(r) ≥ r, wobei m(r) = |R| − max_{|y|≤r} sign(R) z_y(y). m fällt in r nicht.
  - Ohne Koeffizienten ist sign(R) z_y monoton in |y| (wachsend, wenn sign(R) = sign(c), sonst ≤ 0). Dann ist m(r) = |R| − max(0, sign(R) z_y(r)), und r folgt aus einer Bisektion beim Erzeugen der Form.
  - Mit Koeffizienten wertet die Bisektion das Maximum auf 4096 gleichabständigen Stützstellen in [0, r] aus und nimmt r um den relativen Rand 1e−6 zurück.
  - Den genauen Schnitt sichert `in_domain`.

**Startwert des Schnitts** (`base_conic()`): Biconic (c_y, k_y), Toroid und Zylinder (c, k) des Profils. Ein Test prüft die Konvergenz bei stark ungleichen Krümmungen (R_x/R_y = 20 und gekreuzte Lagen).

**Scheitelentwicklung** (ADR 0041, Punkt 1): `value` = 0, `slope` = (0, 0), order = 4.

| Typ | Hessesche (h_xx, h_xy, h_yy) | `rotational4` (aus den Parametern) | (K, A4), wenn `rotational4` |
| --- | --- | --- | --- |
| Biconic | (c_x, 0, c_y) | `radius_x == radius_y` und `conic_x == conic_y` | (k_x, 0), wie `conic` |
| Toroid | (c_R, 0, c) | `radius_of_rotation == radius`, k = 0, keine Koeffizienten (Kugel) | (0, 0) |
| Zylinder | (0, 0, c) | nie | – |

Bei gleichen Parametern bildet der Biconic c einmal und weist es beiden Diagonalen zu (ADR 0041, „Gleichheit der Diagonalen“). Damit sind `first_order`, `prescription` und `seidel` bitgleich zu `conic`.

### 2. Paraxialrechnung je Schnitt

**API** (`rtt/paraxial/paraxial.hpp`):

- `enum class Section { x, y }`.
- `first_order_section(system, path, wavelength, Section)` gibt `FirstOrder` im Schnitt x-z bzw. y-z, mit derselben y-ν-Rechnung wie `first_order`.
- `trace_ray_section(system, path, wavelength, z0, h0, u0, Section)` verfolgt einen paraxialen Strahl in diesem Schnitt; h ist die Höhe in x bzw. y.
- Ein Schnitt ohne Brechkraft ist afokal (`efl` leer), mit derselben Schwelle wie heute.

**Krümmung einer Fläche im Schnitt:**

- Die Fläche liegt mit p_g = o + M p_l im globalen System, M e_z = σ e_z (σ = ±1, nur die Achse ±z ist zugelassen wie bisher). Damit ist M = diag(Q, σ) mit einer 2×2-Matrix Q, det Q = σ.
- Aus z_g − o_z = σ z_l(Qᵀ (x_g − o_x, y_g − o_y)) folgt die **globale Hessesche H_g = σ Q H_l Qᵀ**. Für H_l = c I ist das σ c I, die heutige Regel.
- **Rotationssymmetrisch** (h_xx = h_yy, h_xy = 0 im lokalen System): c genau wie heute über die Prüffunktion aus ADR 0041, Punkt 2. Die Schnitte sind dann bitgleich zu `first_order`, ohne Rundung durch Q Qᵀ.
- **Anamorph:** Die Prüffunktion prüft order ≥ 2 und slope = 0 wie bisher. Statt gleicher Diagonalen verlangt sie ausgerichtete Hauptachsen: |H_g,xy| ≤ `kSymmetryTolerance` · max(|H_g,xx|, |H_g,yy|).
  - Bei Drehungen um ganze Vielfache von 90° gilt das bis auf die Rundung von cos und sin.
  - Sonst gibt es einen `ParaxialError` an der Fläche: „principal axes not aligned with x and y“.
  - Im Schnitt x gilt c = H_g,xx, im Schnitt y gilt c = H_g,yy. Das σ steckt schon in H_g.
- **Scheitellage:** wie ADR 0041, Punkt 2, über `value`.

**Ideale Zylinderlinse** (Entscheidung F3):

- Ihre Brechkraft ist der Tensor φ b bᵀ mit φ = |n|/f wie bei der idealen Linse (ADR 0031, Punkt 6) und b, der Richtung der Brechkraft aus `compile` (global, in der x-y-Ebene).
- Sie verlangt |φ b_x b_y| ≤ `kSymmetryTolerance` · |φ|, also ψ als Vielfaches von 90°, sonst `ParaxialError`.
- Im Schnitt x gilt φ b_x², im Schnitt y gilt φ b_y². Seidel-Beiträge gibt es keine, weil die Seidel-Rechnung anamorph nicht läuft.

**Unverändert** (ADR 0041, Punkt 2):

- `first_order`, `trace_ray`, `prescription` und `seidel` lehnen anamorphe Flächen und die ideale Zylinderlinse weiter ab, mit denselben Meldungen.
- Seidel und `prescription` je Schnitt gibt es nicht. Ein paraxiales Modell vierter Ordnung für anamorphe Flächen ist nicht Teil von v1.

**Erkennung:** `is_anamorphic(system, path)` sagt, ob ein Ereignis des Pfads eine Fläche mit h_xx ≠ h_yy oder h_xy ≠ 0 im lokalen System oder eine ideale Zylinderlinse hat. Die Zielung entscheidet damit ihren Weg vorab und fängt keinen `ParaxialError` ab.

### 3. Zielung je Schnitt

Für einen Pfad ohne anamorphe Fläche läuft alles wie heute. Das ist bitgleich; der Beleg ist der Dump von `make_rays` und `trace`, main gegen Branch.

Für einen anamorphen Pfad hält der Kontext (`sources.cpp`) die folgenden Größen je Schnitt s ∈ {x, y} aus `first_order_section` und `trace_ray_section`.

**Eintrittspupille:** z_ep,s, r_ep,s, `stop_scale_s` und z_ep,ref,s.

- Beide Schnitte haben eine endliche Eintrittspupille, oder bei endlichem Objekt liegt sie in beiden Schnitten im Unendlichen (objektseitig telezentrisch). Ist sie nur in einem Schnitt unendlich, gibt es einen Fehler.
- `label_sign` (ADR 0007, Nachtrag #35 B) muss in beiden Schnitten gleich sein, sonst Fehler.

**Systemapertur:**

| Art | r_ep,s |
| --- | --- |
| Durchmesser der Eintrittspupille | EPD/2 in beiden Schnitten (die Eintrittspupille ist per Definition rund) |
| `stop_size` | r_stop / \|`stop_scale_s`\| |
| `object_na`, paraxial gelesen | u_m · \|z_ep,s − z_obj\|, telezentrisch u_m |
| `object_na`, real gelesen (ADR 0040) | Fehler „not for anamorphic systems (ADR 0042)“; der reale Randstrahl liegt in einem Meridian, die Blendenfigur eines anamorphen Systems ist keine Kreisscheibe |
| bildseitige Blendenzahl | Fehler: EPD = EFL/F# ist mehrdeutig, weil die EFL je Schnitt verschieden ist |

**Paraxialer Startstrahl:** eine Gerade, deren x-Verlauf durch (z_ep,x; a) und deren y-Verlauf durch (z_ep,y; b) geht, mit a = s_x r_ep,x und b = s_y r_ep,y.

- Objekt im Unendlichen: Die Richtung kommt aus dem Feld, die Punkte in den beiden Ebenen.
- Endliches Objekt: die Steigungen (a − h_x)/(z_ep,x − z_obj) und (b − h_y)/(z_ep,y − z_obj).
- Telezentrisch: die Steigungen a und b.
- Mit z_ep,x = z_ep,y ist das der heutige Strahl.

**Reale Zielung:** der Newton aus ADR 0007, unverändert.

- Das Ziel in der Blende ist (s_x r_ep,x `stop_scale_x`, s_y r_ep,y `stop_scale_y`). Eine runde Eintrittspupille bildet sich in der Blende als Ellipse ab; bei `stop_size` ist das Ziel wieder die Kreisscheibe der Blende.
- Die Schrittweite h ist das Maximum der heutigen Formel über beide Schnitte.

**`Aiming::Paraxial`:** gibt den Startstrahl zurück.

**Felder:**

- Winkel bei endlichem Objekt und paraxiale Bildhöhe rechnen jede Komponente im eigenen Schnitt: den Objektpunkt aus z_ep,ref,s und die Einheitsbildhöhe aus `first_order_section` des Schnitts.
- Objekthöhen und Winkel bei unendlichem Objekt brauchen keine Paraxialdaten.

**Startebene** (`lowest_z`): je Schnitt mit z_ep,s, dann das Minimum; als Bündelradius das Maximum der r_ep,s.

**`AimReference`** speichert die Daten je Schnitt. Damit zielen gestörte Prüflinge eines anamorphen Nennsystems und die Optimierung über den Bezug wie heute.

**`stop_radius` und `paraxial_stop_radius`** geben einen Wert, wenn er in beiden Schnitten gleich ist (`stop_size` oder runde Blendenfigur), sonst einen Fehler.

**Größen ohne Schnitt:** Objekt- und Bildindex sowie die Bildrichtung sind in beiden Schnitten gleich (dieselben Medien und Reflexionen). Der Kontext nimmt sie aus dem Schnitt y.

### 4. Bleibt ein Fehler (nicht in S2)

- **Austrittspupille je Schnitt** (OPD, Wellenfront, PSF, MTF, Jones-Pupille):
  - Ohne Bezug bleibt es beim `ParaxialError`. Die Bezugssphäre einer astigmatischen Austrittspupille ist ein eigenes Thema.
  - Mit dem Bezug eines Nennsystems laufen sie wie heute.
- **Weitere Analysen:** Feldkurven, Farbfehler und Geister-Startstrahlen anamorpher Systeme.
- **Optimierung und Toleranzierung:**
  - Paraxiale Operanden je Schnitt (`efl_x`, `efl_y`, …), Entscheidung F4. Die Operanden efl, bfl und Vergrößerung melden weiter `merit.operand_unsupported`.
  - Toleranzarten auf R_x, R_y und die Konik je Achse, Entscheidung F5. `validate` meldet `tolerances.target_invalid` wie in ADR 0041, Punkt 6; Nachtrag zu ADR 0035.

### 5. Modell, Datei, Ergebnisformat, Python

- **Modell und Datei:** Structs `Biconic`, `Toroid`, `Cylinder` in `BaseShape`, nach der Checkliste „Neuer Flächentyp“ in `AGENTS.md`. Schema 0.9 in Welle 3 (ADR 0041, Punkt 7): Rebase nach S1, vor S3.
- **Toleranzklassen:** Biconic, Toroid und Zylinder bekommen den eigenen Grund „Art für diesen Typ nicht definiert“, den S1 einführt (Entscheidung F2 von S0).
- **Ergebnisformat** (Nachtrag zu ADR 0023, nächste Version):
  - `SurfaceLayout.shape` bekommt `biconic`, `toroid` und `cylinder`.
  - `curvature`, `conic_constant` und `coefficients` beschreiben den y-Schnitt bzw. das Profil.
  - Neu ist `curvature_x`: c_x, c_R bzw. 0; für die bestehenden Typen gleich `curvature`. Beim Biconic kommt `conic_constant_x` dazu.
- **Python:**
  - Klassen `Biconic`, `Toroid`, `Cylinder`;
  - `Section`, `first_order_section` und `trace_ray_section` in `raytatouille.paraxial`;
  - `SurfaceLayout` mit den neuen Feldern.

### 6. Abnahme

1. **Zylinderlinse**, plankonvex: gekrümmte Seite (Radius R im y-Schnitt) vorn, plane Rückseite, Dicke t, Index n.
   - y-Schnitt: efl = R/(n − 1), unabhängig von t, weil die Planfläche nichts beiträgt (P = P₁ + P₂ − (t/n) P₁ P₂ mit P₂ = 0); bfl = efl − t/n.
   - x-Schnitt: afokal.
   - Reale Strahlen: Ein Strahl in der x-z-Ebene parallel zur Achse bleibt parallel. Ein Strahl mit kleiner Höhe y schneidet die Achse bei bfl + O(y²), geprüft bei zwei Höhen.
2. **Biconic mit gleichen Achsen gegen `conic`:**
   - `vertex_expansion`, `first_order` und `seidel` bitgleich;
   - `sag` und `grad` auf einem Raster bis auf wenige ulp gleich (Schranke im Test begründet);
   - Schnittpunkte eines Bündels auf 1e−12 mm gleich.
3. **Toroid:**
   - `sag` gegen die geometrische Definition (Abstand zur Drehachse gleich |R − z_y(y)|) auf 1e−12 relativ;
   - mit R = `radius`, k = 0 gegen die Kugel;
   - `grad` gegen zentrale Differenzen.
4. **Zylinder** gegen den Toroid mit großem R und gegen die Profilformel.
5. **`max_radius` und `in_domain`:** Punkte innerhalb von `max_radius` liegen im Gebiet. Ein Strahl zwischen Kreis und Gebietsgrenze trifft. Ein Strahl außerhalb des Gebiets endet als `Missed` bzw. `NoConvergence` wie heute, nie mit NaN im Ergebnis.
6. **Erste Ordnung je Schnitt** gegen eine unabhängige Matrixrechnung im Test, mit efl, bfl und Eintrittspupille je Schnitt:
   - gekreuzte Zylinder (90°);
   - ein Biconic-Singulett;
   - ein Toroid vor der Blende (z_ep,x ≠ z_ep,y);
   - die ideale Zylinderlinse mit ψ = 0° und 90°.
7. **Fehler:**
   - Biconic und ideale Zylinderlinse um 45° gedreht: `ParaxialError` mit Fläche und Pointer.
   - `first_order` lehnt anamorphe Pfade weiter ab.
   - Die Fehler der Zielung aus Punkt 3, je ein Fall.
8. **Zielung:**
   - Für das System mit Toroid vor der Blende treffen die realen Hauptstrahlen von Feldern in x und in y die Blendenmitte, und die Randstrahlen das Ziel aus Punkt 3, Status geprüft.
   - Für rotationssymmetrische Systeme ist der Dump von `make_rays` und `trace` bitgleich, main gegen Branch, wie in S0.
9. **Datei, Schema, Python:** Roundtrip, Schema-Tests, Lesetests, Layout und Bitvergleich C++ gegen Python, mit Inhaltswache.

## Verworfen

- **Volle anamorphe Paraxialrechnung mit 4×4-Matrizen** (gedrehte anamorphe Flächen in beliebiger Lage): Das deckt v1 nicht; die Schnitte verlangen ausgerichtete Hauptachsen. Systeme mit schräg liegenden Zylindern zielen über den Bezug eines Nennsystems oder erst in einer späteren Version.
- **Flache Schnitte über einen optionalen Radius** im Biconic bzw. Toroid (OpticStudio: 0 = unendlich): Die Prüfung „endlich und ≠ 0“ würde je Typ anders. Ein eigener Typ `cylinder` ist eindeutig (F1).
- **Den Term α₁ y² des Toroids übernehmen:** Er verschiebt die Scheitelkrümmung gegenüber 1/`radius` und doppelt den Radius (F2).
- **Den anamorphen Weg der Zielung durch Abfangen des `ParaxialError` wählen:** Dann hinge die Wahl am Text einer Meldung. `is_anamorphic` entscheidet vorab.
- **Nur den y-Schnitt für die Zielung nutzen:** Das ist falsch, sobald eine anamorphe Fläche vor der Blende liegt (z_ep,x ≠ z_ep,y). Die reale Zielung fände die Blende dann nur bei kleinen Abweichungen.
- **Gebiet nur über `max_radius`** (Kreis): Strahlen zwischen Kreis und Gebietsgrenze würden still als verfehlt gezählt, beim Biconic mit stark verschiedenen Achsen ein großer Teil der Fläche.
