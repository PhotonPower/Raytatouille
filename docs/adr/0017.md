# ADR 0017: Kittglieder: Material je Segment

**Status:** angenommen (2026-10-04)

## Kontext

Bis Schema 0.1 hat ein `Element` genau ein optionales Material. Ein Kittglied (z. B. ein
Achromat aus N-BK7 und F2) lässt sich damit nicht beschreiben: Eine `Lens` mit drei Flächen hätte
überall dasselbe Glas, und zwei getrennte Linsen mit zusammenfallender Kittfläche ergäben im
Nullspalt einen falschen Übergang über Luft (falsche Totalreflexion, ab M3 zwei statt eines
Fresnel- bzw. Coating-Übergangs). In #14 wurden drei Optionen abgewogen; der Koordinator hat im
Auftrag des Maintainers Option 1 gewählt. Umsetzung des Formats in #26, Medienfolge in
`rtt-compile` in #27.

## Entscheidung

1. **Segmente:** `Lens` und `Plate` mit N Flächen haben N − 1 Segmente; Segment i liegt zwischen
   Fläche i und Fläche i + 1 (nullbasiert, Reihenfolge von `surfaces`). Jedes Segment hat ein
   Material (Katalogverweis `"KATALOG:NAME"`).
2. **Modell:** `Element` behält `std::optional<std::string> material` als Kurzform „ein Material
   für alle Segmente“ und bekommt `std::vector<std::string> segment_materials` mit einem Eintrag je
   Segment. Höchstens eine der beiden Formen ist gesetzt. `Element::segment_material(i)` liefert
   das Material von Segment i in beiden Formen. Mirror, ThinElement, Stop und Detector bleiben
   unverändert und lassen keine Liste zu.
3. **Datei:** derselbe Schlüssel `"material"`, entweder als String (Kurzform) oder als nicht leeres
   Array von Strings (eine Angabe je Segment):
   `"material": ["SCHOTT:N-BK7", "SCHOTT:F2"]`. Der Writer schreibt genau die gelesene Form; ein
   String bleibt ein String, ein Array bleibt ein Array (auch mit einem Eintrag). Damit gilt der
   bitgleiche Roundtrip ohne Normalisierung.
4. **Validierung** (`rtt::model::validate`): Lens und Plate brauchen genau eine der beiden Formen;
   die Liste hat genau N − 1 Einträge; leere Einträge sind Fehler am Listeneintrag
   (`.../material/<i>`), alle anderen Fehler am Materialfeld (`.../material`). Ein leeres Array ist
   bereits ein Strukturfehler des Parsers.
5. **Version und Migration:** `kSchemaVersion` steigt von 0.1.0 auf 0.2.0. `rtt-io` liest weiter
   0.1-Dateien: Jede 0.1-Datei ist inhaltlich eine 0.2-Datei, die Migration setzt nur die Version;
   ein Array als Material in einer Datei mit 0.1 ist ein Fehler. Geschrieben wird immer 0.2.0.
   Das JSON-Schema beschreibt nur die aktuelle Version; ältere Dateien bringt `rtt format` auf 0.2.

## Verworfen

- **Option 2 aus #14, getrennte Elemente mit zusammenfallenden Flächen:** braucht eine Heuristik
  „zusammenfallend“ mit Toleranz und Sonderfälle für Pose und Form; zwei Übergänge statt einem.
- **Option 3 aus #14, eigenes Element `CementedGroup`:** verdoppelt dieselbe Information, die
  `Lens` mit Material je Segment schon trägt.
- **Nur eine Liste im Modell (ohne Kurzform):** `rtt-compile` liest heute `material`; die
  Medienfolge für Kittglieder ist ein eigenes Issue (#27). Außerdem ginge die Kurzform beim
  Schreiben verloren (kein bitgleicher Roundtrip ohne zusätzliches Merkmal).
- **Eigener Schlüssel `"materials"`:** zwei Schlüssel für dieselbe Größe, und Dateien müssten
  den Ausschluss beider Schlüssel ausdrücken.
- **Normalisieren beim Schreiben** (Array mit einem Eintrag oder lauter gleichen Einträgen als
  String): Was gelesen wurde, würde anders geschrieben.

## Folgen

- Schema 0.2.0; alle Referenzdateien sind mit `rtt format` neu geschrieben (nur die Version
  ändert sich). Neues Beispiel `tests/reference/m2/achromat.rtt.json`.
- `segment_materials` ist das letzte Datenelement von `Element` mit eigenem Initialisierer, damit
  bestehende Aggregat-Initialisierungen `{name, kind, pose, material, surfaces}` gültig bleiben.
- Bis #27 wertet `rtt-compile` nur die Kurzform aus: Ein Element mit Materialliste gilt dort
  noch als Element ohne Material, und eine `Lens`/`Plate` mit mehr als 2 Flächen auf einem
  automatischen Pfad bleibt ein Kompilierfehler. #27 setzt die Regel aus #14 um: `Refract` an
  Fläche i wechselt ins Segment i, an der letzten Fläche ins Umgebungsmedium.
- Ein Mangin-Spiegel mit mehreren Gläsern ist nicht Teil dieser Entscheidung; `Mirror` nimmt
  weiterhin nur ein Substratmaterial als String.
- Nachtrag #27: `rtt-compile` wertet beide Formen aus; die Medienfolge folgt den Segmenten, der
  Kompilierfehler für mehr als 2 Flächen auf dem automatischen Pfad entfällt. Ergänzend
  festgelegt: Elemente schachteln nicht, und eine innere Fläche einer `Lens`/`Plate`, die ein
  Pfad von außen erreicht, ist ein Kompilierfehler. Die vollständige Regel steht in
  `docs/architecture.md` unter „Medien entlang eines Pfads“.
