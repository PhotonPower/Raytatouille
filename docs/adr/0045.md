# ADR 0045: CSV-Flächentabelle und ZMX-Export (M8 I2)

**Status:** angenommen (Maintainer, 2026-11-08, #362)

## Kontext

I2 (#318) bringt zwei Austauschwege:
- eine eigene CSV-Flächentabelle in beide Richtungen;
- den ZMX-Export des sequenziellen Teils, die Umkehrung des Imports aus ADR 0044.

- **Vorschlag:** #318, Kommentar 6714445817 (v2), vom physik-reviewer in zwei Runden geprüft.
- **Entscheidung:** Der Maintainer folgt allen Empfehlungen zu F1 bis F9 (Kommentar 6714452708, 2026-11-08).
- **Nicht in I2:** CodeV-`.seq` (keine frei zugängliche Formatbeschreibung, #318); gefaltete und gekippte Systeme (Punkt 2); eine Python-Bindung.

**Bestand im Code (main a3c7b424):**
- Der ZMX-Import (ADR 0044 mit den Nachträgen PR B und PR C) legt die Lesart der Schlüsselwörter fest; der Export übernimmt sie.
- Es gibt weder Schreiber noch Leser für CSV in C++. `raytatouille.reports.to_csv` in Python schreibt Reports mit LF und kürzesten Zahlen (docs/architecture.md, Abschnitt Reports). Die Bibliothek schreibt bewusst keine Report-Tabellen. Die Flächentabelle ist dagegen ein Austauschformat für Systeme und gehört nach `rtt-io`.
- Das kompilierte System liefert die Ereignisse eines Pfades in Reihenfolge, die globalen Rahmen der Flächen (`to_global`) und das Medium nach jedem Ereignis als Namen (`CompiledMedium::reference`, z. B. `SCHOTT:N-BK7`). Formparameter, Aperturen und Wechselwirkungen stehen im Modell.

**Quellen** (Zeilen in `docs/quellen.md`):
- [UG] und [ZR] wie ADR 0044; der Export braucht keine neuen Schlüsselwörter.
- RFC 4180, Abschnitt 2 (CSV), gelesen.
- C++20 (N4861), 20.19.2 [charconv.to.chars], Absätze 2, 7 und 8 (kürzeste Darstellung).
- Hergeleitet in #318: die Luftwellenlänge (Punkt 4) und die gespiegelte Form (Punkt 2).

## Entscheidung

### 1. Grundsatz

- Der Export schreibt nur, was der Import aus ADR 0044 genau so wieder liest. Zwei Formen kehren als andere Art zurück, mit derselben Fläche: eine `even_asphere` mit allen A = 0 als `conic` (der Import schneidet Nullen ab und nimmt dann `STANDARD`), eine `odd_asphere` mit c = 0 und k ≠ 0 mit k = 0 (die Konik wirkt bei c = 0 nicht).
- **Jeder Fehlerweg des Imports hat einen Fehler des Exports.** Eine exportierte Datei scheitert nie beim Import (Abnahme 3).
- Fehler sind Exceptions an der API-Grenze (Regel 3), Warnungen kommen mit dem Ergebnis.

### 2. Koaxiale Teilmenge

ZMX-Export und Tabelle nehmen nur koaxiale Systeme an (F1).
- **Definition:** Jeder Scheitel liegt auf der z-Achse. Jede Flächenachse ist ±e_z, mit lokalem x ∥ ±e_x und y ∥ ±e_y. Erlaubt sind also die Einheit und die Drehungen um 180° um x, y oder z.
- **Schwelle:** eine eigene Konstante 10⁻¹² (mm bzw. auf den Einheitsvektoren), gewählt wie die Symmetrieprüfung von `first_order`; deren Konstante liegt in einem privaten Header von `rtt-paraxial`. Dezentrierungen bis 10⁻¹² mm entfallen damit still.
- **Spiegel auf der Achse** sind erlaubt. Der Rahmen von OpticStudio dreht sich am Spiegel nicht ([UG] „Thickness“), also werden die Dicken nach einem Spiegel von selbst negativ und nach zwei Spiegeln wieder positiv. Beispiel `m1/paraboloid_mirror`: `CURV -0.005`, `DISZ -100`.
- **Gekippte Achse (−e_z):** Die Form wird gespiegelt: R → −R, A_i → −A_i, die Konik bleibt.
  - Hergeleitet: Mit der Achse −e_z ist z_global = −f(r). Die Wurzel der Konik enthält nur c², also hat −f die Krümmung −c, dieselbe Konik und die Koeffizienten −A_i.
  - Kreis, Rechteck und Ellipse sind unter x → −x und y → −y symmetrisch; die Drehungen um 180° ändern sie nicht.
- **Alles andere** ist der Fehler `export.not_coaxial` mit der Fläche.
- **Begründung:** OpticStudio verlangt, dass die Dicke nach jedem Spiegel das Vorzeichen wechselt, unabhängig von 180°-Drehungen ([UG] „Thickness“: „This fundamental convention cannot be circumvented through the use of coordinate rotations of 180 degrees“). Bei uns darf ein Element hinter einem Spiegel in beiden Lagen stehen (ADR 0028, Punkt 4). Ein gefalteter Export müsste die Rahmen umorientieren, und ohne OpticStudio ist das nicht prüfbar. Gefaltete und gekippte Systeme kommen in ein Folge-Issue.

### 3. Pfad, Ereignisse, Elemente

- Exportiert wird ein Pfad, standardmäßig Pfad 0 (F6).
  - Weitere Pfade entfallen mit der Warnung `export.paths_dropped`.
  - Flächen, die nicht auf dem Pfad liegen, geben die Warnung `export.surface_off_path`.
- Exportiert wird eine Konfiguration, standardmäßig Konfiguration 0, mit aufgelösten Parametern (`resolve_parameters`); ohne Konfigurationen ist das das Nennsystem. Mehrere Konfigurationen ohne ausdrückliche Wahl sind der Fehler `export.multi_config`.
- Variablen, Grenzen, gebundene Parameter, Optimierung und Toleranzen werden nicht geschrieben; die Datei enthält die Werte.

| Fall | Code | Grund bzw. Fehlerweg des Imports |
|---|---|---|
| ein Ereignis, das nicht das des automatischen Pfades für seine Elementart ist (z. B. Reflect an einer Linse, Refract an einem Spiegel, Reflect an einem dünnen Element), Ordinary, Extraordinary, Ordnung ≠ 0 | `export.event_unsupported` | ZMX kennt je Fläche nur die Art aus dem Glas |
| dieselbe Fläche mehrmals auf dem Pfad (Doppeldurchgang) | `export.event_unsupported` | doppelte Elemente |
| Spiegel im Glas (Mangin) | `export.mirror_in_glass` | `zmx.mirror_in_glass` |
| Element `stop`, `thin_element` oder `detector` mit Glas davor oder dahinter, etwa die Blende in L2 von `m2/cooke_triplet.rtt.json` | `export.element_in_glass` | Linse mit Flächenblende bzw. `zmx.image_in_glass` |
| Objektmedium ≠ Umgebung, und das erste Element ist keine Linse | `export.object_medium_unsupported` | `zmx.object_medium_unsupported` |
| ein Objektmedium bei Objekt im Unendlichen | lehnt schon `validate` ab (`object.medium_infinite`) | `zmx.object_medium_infinite` |
| das letzte Ereignis ist kein Detektor | `export.image_missing` | der Import nimmt die letzte Fläche als Bildfläche (`zmx.image_in_glass` oder eine still umgedeutete Fläche) |
| ein Detektor vor dem letzten Ereignis | `export.event_unsupported` | dito |
| keine Blende (F8) | `export.stop_missing` | „no STOP surface“ (`zmx.parse`) |
| Rechteck oder Ellipse an der Blende | `export.aperture_unsupported` | `zmx.aperture_unsupported` |

Die Zeilen zum Detektor sind eine Ergänzung gegenüber dem Vorschlag aus dem Review dieses ADR (Regel 10), ebenso `export.name_changed` und die Regel für `AIR` in Punkt 4.

Zu F8: Eine Blende auf Fläche 1 mit EPD/2 würde real gezielte Randstrahlen beschneiden (ADR 0044, Punkt 8, deshalb dort 1,1 · v), und jeder andere Radius wäre geraten. Betroffen ist z. B. `m1/paraboloid_mirror`.

### 4. ZMX-Export

**n_Luft** ist überall n_Luft(λ_vac,ref, 20 °C, 1 atm) nach Ciddor, mit der Vakuumwellenlänge der Referenz (`PWAV`), wie beim Import.

**Luftwellenlänge:** λ_Luft = λ_vac / n_Luft(λ_vac).
- Hergeleitet: Das ist dieselbe Gleichung λ_vac = λ_Luft · n_Luft(λ_vac), die der Import als Fixpunkt löst (`compile::line_vacuum_wavelength_um`), nur nach λ_Luft aufgelöst. Sie braucht keine Iteration.
- Im Review nachgerechnet: Vakuum → Luft → Vakuum bei 200 000 Werten zwischen 0,3 und 2,5 µm bitgleich oder ±1 ulp.

**Form der Datei:**
- Zeilen in dieser Reihenfolge: `VERS`, `MODE SEQ`, `NAME`, `UNIT MM`, die Kopfzeilen oben, die Flächen, `MNUM 1`;
- Zeilen eines Flächenblocks eingerückt (der Import ordnet eingerückte Zeilen der letzten `SURF` zu);
- CRLF wie OpticStudio;
- UTF-8 ohne BOM; der Import liest ASCII und UTF-8;
- `NAME` ohne Steuerzeichen: CR, LF und andere Zeichen unter 0x20 werden Leerzeichen, mit der Warnung `export.name_changed`. Sonst bräche der Name die Zeile.

**Zahlen (F3):** die kürzeste Darstellung, die beim Lesen denselben double gibt (`std::to_chars` ohne Format, [charconv.to.chars]).
- Der Import liest sie bitgleich zurück. Nur R → 1/R → 1/(1/R) rundet um höchstens etwa 1,5 ulp.
- OpticStudio selbst schreibt `%.12E`, im OISC-Korpus bei `CURV` mit 18 Nachkommastellen.

**Grenze (F7):** Ob OpticStudio die exportierten Dateien liest, ist ungeprüft. Das bleibt offen, bis eine Datei in OpticStudio geöffnet wurde.

### 6. Kanonische Form

Ein System ist **kanonisch**, wenn:
- der Baum flach ist (Elemente direkt unter der Wurzel, keine Baugruppen);
- das erste Element absolut bei z = 0 liegt;
- jedes weitere Element und jede innere Fläche `relative_to_preceding` mit (0, 0, t) liegt, ohne Drehung;
- keine Fläche gekippt ist;
- `object.reference` fehlt;
- der einzige Pfad `auto` ist;
- gleiche Segmentmaterialien als `material` stehen.

Die Tabelle liefert diese Form. Der ZMX-Import liefert sie auch, nur kann er das erste Element hinter entfallenen Dummies bei z₁ ≠ 0 legen.

### 7. CSV-Flächentabelle

**Inhalt (F2):** eine Zeile für das Objekt und eine je Fläche des Pfades, in Pfadreihenfolge.
- Wellenlängen, Felder, Systemapertur und Umgebung bleiben im JSON.
- **Einlesen:** Es braucht ein Basissystem. Ersetzt werden dessen Baum, Objekt und Blende; der Pfad wird `auto`.
- Was im Basissystem auf den alten Baum verweist, entfällt mit der Warnung `table.base_dropped` und dem Namen des Blocks: weitere Pfade, Optimierung, Toleranzen, Parametertabelle, Konfigurationen.
- Am Ende laufen `validate` und `compile`; ein Fehler dort wird `table.invalid_result` mit der Meldung des Originals.

**Format** nach RFC 4180, Abschnitt 2:
- **Kopfzeile** mit den Spaltennamen unten (Regel 3). Geschrieben wird diese Reihenfolge; gelesen wird nach Namen, die Reihenfolge ist frei.
- **Trenner und Feldzahl:** Komma als Trenner; jede Zeile hat gleich viele Felder (Regel 4).
- **Anführungszeichen:** Felder mit Komma, Anführungszeichen oder Zeilenumbruch stehen in Anführungszeichen; ein Anführungszeichen darin wird verdoppelt (Regeln 6 und 7).
- **Zeilenende (F9):** Geschrieben wird CRLF (Regel 1), gelesen werden CRLF und LF; der letzte Satz darf ohne Zeilenende enden (Regel 2).
- **Leerzeichen** gehören zum Feld (Regel 4); eine Zahl mit Leerzeichen ist `table.value`.
- **Kodierung:** UTF-8. Ein BOM wird beim Lesen übergangen. Die Grammatik von RFC 4180 kennt nur ASCII (TEXTDATA); Abschnitt 3 erlaubt andere Zeichensätze über den Parameter `charset` („other character sets … may be used in conjunction with the 'charset' parameter“). Namen dürfen hier also Umlaute tragen.
- **Zahlen** wie in Punkt 4; `Infinity` für das Objekt im Unendlichen.
- **Leere Felder:** bei `radius` die Ebene, bei `conic`, `a4` … `a16` und dem Innenradius 0, sonst „nicht gesetzt“. Der Wert 0 wird dort immer leer geschrieben.
- **Versionierung:** Unbekannte Spalten sind ein Fehler. Neue Spalten kommen nur hinzu, und bestehende behalten ihre Bedeutung. Das Format steht in `docs/dateiformat.md`. Das Modell ändert sich nicht, also gibt es keinen Schemasprung (Regel 9).

**Spalten:**

| Spalte | Inhalt |
|---|---|
| `row` | `object` (erste Zeile) oder `surface` |
| `surface` | Flächen-ID |
| `element`, `kind` | Elementname und Art (`lens`, `plate`, `mirror`, `thin_element`, `stop`, `detector`). Aufeinanderfolgende Zeilen mit demselben Element bilden ein Element; ein Name kommt nur einmal vor |
| `shape` | `plane`, `conic`, `even_asphere` |
| `radius`, `conic` | R in mm, Konik |
| `a4`, `a6`, `a8`, `a10`, `a12`, `a14`, `a16` | Asphärenkoeffizienten in mm^(1−2i), wie `EVENASPH`; weitere Terme: `export.surface_unsupported` |
| `thickness` | Abstand zum Scheitel der nächsten Zeile längs z in mm; beim Objekt der Abstand zur ersten Fläche oder `Infinity` |
| `material` | Medium hinter der Fläche (`KATALOG:NAME`, `CONST:…`, leer = Umgebung); bei Spiegeln leer; beim Objekt das Objektmedium |
| `aperture`, `aperture_1`, `aperture_2` | `circular` (Radius, Innenradius), `rectangular` bzw. `elliptical` (Halbbreiten x, y) oder leer |
| `stop` | `true` an der Blende, sonst leer |
| `focal_length`, `object_distance` | ideale Linse |

**Regeln:**
- **Einlesen:** Gebaut wird die kanonische Form. Die Materialien einer Linse kommen aus `material` ihrer Flächen; sind sie verschieden, werden sie `segment_materials`.
- **Fehler** `table.parse` (Syntax, `;` statt Komma), `table.column` (fehlende oder unbekannte Spalte), `table.value` (unlesbarer oder unzulässiger Wert), `table.duplicate` (Element oder ID doppelt), je mit Zeile und Spalte; eine fehlende Spalte und `table.invalid_result` mit 0.
- **Excel:** Mit deutscher Einstellung schreibt Excel `;` und Dezimalkomma und speichert nur 15 Stellen. Ein `;` in der Kopfzeile gibt `table.parse` mit diesem Hinweis. Die 15 Stellen sind eine Grenze der Tabellenkalkulation, nicht des Formats.
- **Schreiben:** Es gelten die koaxiale Teilmenge und die Fehler aus den Punkten 2 und 3 mit denselben `export.*`-Codes. Anders als beim ZMX-Export sind `CONST:`, `VACUUM` und `object_distance` erlaubt. Coatings geben auch hier `export.coating_dropped`, Spiegelmaterialien `export.mirror_material_dropped`.

**Bitgleich** heißt:
- **Tabelle → System → Tabelle** gibt denselben Text, wenn die Tabelle einmal von uns geschrieben wurde (Idempotenz).
- **System → Tabelle → System** gibt dasselbe System, wenn es kanonisch ist (Punkt 6), das Schreiben keine Warnung gibt und das Basissystem das System selbst ist, ohne die Blöcke aus `table.base_dropped`.
- **Andere Systeme** (absolute Posen, z₁ ≠ 0, Baugruppen) kommen mit gleichen Scheiteln und gleichen Flächen in globalen Koordinaten zurück, auf 10⁻¹² mm relativ zum ersten Scheitel. Drehungen um 180° entfallen dabei; die Form ist dann gespiegelt (Punkt 2).

### 8. Diagnosecodes

Neue Erzeuger `export` und `table` in `rtt-diagnostics/codes.hpp` und `docs/diagnostics.md` (F5). Das ändert den öffentlichen Header einer anderen Bibliothek; dieses ADR ist der Beschluss dafür (Regel 8), wie ADR 0044, Punkt 11. Die Liste der Erzeuger in `libs/rtt-diagnostics/tests/test_codes.cpp` wird ergänzt (Regel 2, vom Maintainer freigegeben).

- **Fehler `export`:**
  - Teilmenge und Pfad: `export.not_coaxial`, `export.multi_config`, `export.event_unsupported`;
  - Elemente: `export.mirror_in_glass`, `export.element_in_glass`, `export.object_medium_unsupported`, `export.stop_missing`, `export.image_missing`;
  - System: `export.aperture_unsupported`, `export.environment_unsupported`, `export.limit_exceeded`;
  - Flächen und Gläser: `export.material_unsupported`, `export.glass_ambiguous`, `export.surface_unsupported`, `export.interaction_unsupported`.
- **Warnungen `export`:** `export.paths_dropped`, `export.surface_off_path`, `export.paraxial_opd`, `export.mirror_material_dropped`, `export.coating_dropped`, `export.name_changed`.
- **Fehler `table`:** `table.parse`, `table.column`, `table.value`, `table.duplicate`, `table.invalid_result`.
- **Warnung `table`:** `table.base_dropped`.

### 9. Abnahme

1. **Cooke-Triplet über Export und Import** (Abnahme aus #318), mit `m2/cooke_triplet_surface_stop.rtt.json`, einmal über ZMX und einmal über die Tabelle:
   - EFL und BFL gleich auf 10⁻¹² relativ;
   - Spot-RMS je Feld auf 10⁻⁹ mm;
   - Scheitel relativ zum ersten auf 10⁻¹² mm, Radien auf 10⁻¹⁵ relativ, Wellenlängen auf 10⁻¹⁵ relativ.

   **Grenze 10⁻⁹ mm:** Beide Systeme unterscheiden sich nur um wenige ulp (R um etwa 1,5 ulp, λ um höchstens 1 ulp). Die reale Zielung läuft auf beiden denselben Weg, also unterscheiden sich die Ergebnisse um Rundungsgrößen, um Größenordnungen unter 10⁻⁹ mm. Die Grenze ist gleich der Abbruchschwelle der Zielung, `kAimTolerance` = 10⁻⁹ mm (`rtt/trace/sources.hpp`), hat also keine Reserve: Fiele die Zahl der Zielschritte verschieden aus, könnte der Unterschied bis an `kAimTolerance` reichen; der Test zeigte das.

   `m2/cooke_triplet.rtt.json` (Blende als Element im Glas) gibt `export.element_in_glass`.
2. **Rundreise der ZMX-Testfälle:** Jeder koaxiale Fall aus `libs/rtt-io/tests/zmx` wird importiert, exportiert und wieder importiert. Verglichen wird über eine Zuordnung der IDs:
   - Scheitel und Objektabstand relativ zum ersten Scheitel auf 10⁻¹² mm;
   - R, Wellenlängen, `image_fnumber` und `object_na` auf 10⁻¹⁵ relativ (n_Luft hin und zurück, ±1 ulp);
   - alles andere bitgleich, die Dicken bei Fällen ohne entfallene Dummies ebenfalls.
3. **Alle Referenzsysteme:** Jedes System unter `tests/reference/` läuft durch den Export. Entweder gelingen Export und Import und geben dieselbe erste Ordnung (10⁻¹² relativ) und dieselben Spot-RMS (10⁻⁹ mm), wo `first_order` geht. Oder der Export scheitert mit einem `export.*`-Code. Nie ein Fehler beim Import.
4. **Unabhängige Sollwerte:**
   - Für ein Singulett vergleicht der Test die ZMX-Ausgabe Wort für Wort mit einer Solldatei. Ein Python-Skript schreibt sie aus der Beschreibung, mit eigenem Ciddor (NIST, Gl. (A21)–(A41)) für λ_Luft und F/# mal n_Luft. Die Zahlen sind bitgleich, außer λ, `FNUM` und `OBNA` (≤ 10⁻¹⁵ relativ).
   - Dasselbe für die Tabelle.
5. **CSV:**
   - Idempotenz Tabelle → System → Tabelle;
   - System → Tabelle → System bitgleich in kanonischer Form;
   - Lesefälle mit Anführungszeichen, LF und CRLF, BOM, leeren Feldern und `;` aus Excel;
   - jeder `table.*`-Fehler mit Zeile und Spalte (oder 0);
   - das Basissystem mit `table.base_dropped`.
6. **Fehler und Warnungen:** jeder neue Code mit einem Fall; dazu eine Prüfung, dass die Registry keinen `export`- oder `table`-Code ohne Fall hat.
7. **CLI:** Gutfall und Fehlerfall je Richtung mit den Exit-Codes; die Ausgabe Tabelle → JSON besteht `rtt format --check`.
8. **Inhaltswächter:** In Abnahme 1 kommen alle Strahlen an, und die Felder geben verschiedene Spot-RMS.

## Verworfen

- **Gefaltete und gekippte Systeme in I2:** Die Vorzeichenregel von OpticStudio nach Spiegeln verlangt umorientierte Rahmen und gespiegelte Formen. Ohne OpticStudio ist das nicht prüfbar (Punkt 2).
- **Eine vollständige Systemdatei als CSV** (Spalte „Satzart“ für System, Wellenlängen, Felder und Flächen): Für die Bearbeitung in einer Tabellenkalkulation genügt die Linsentabelle; das übrige System bleibt im JSON (F2).
- **Zahlen im Stil von OpticStudio** (`%.12E`, 13 Stellen): Damit gäbe es keine Bitgleichheit über ZMX und Tabelle (F3).
- **`CONST:` als Modellglas im ZMX-Export:** Zemax legt die Dispersion der Modellgläser nicht offen; ein Ersatz wäre ein anderes Glas (F4, ADR 0044, Punkt 7).
- **Eine Blende auf Fläche 1 bei Systemen ohne Blende:** Jeder Radius wäre geraten (F8).
- **LF in der Tabelle wie die Reports aus Python:** Die Tabelle dient dem Austausch mit Tabellenprogrammen, RFC 4180 verlangt CRLF; gelesen wird beides (F9).

## Folgen

## Nachtrag (#318, PR B, 2026-11-09): Umsetzung des ZMX-Exports

- **`save_zmx` gibt die Warnungen zurück** (`std::vector<model::Diagnostic>`, `[[nodiscard]]`) statt `void`. Sonst gingen sie beim Schreiben in eine Datei still verloren; `rtt export` schreibt sie nach stderr wie `rtt import`.
- **Unbekannter Pfadname, Konfigurationsindex außerhalb:** `std::invalid_argument` (Fehlbedienung der API, kein Code). Ein System, das nicht kompiliert, gibt die `compile::CompileError` von `compile()` weiter. `rtt export` meldet beides mit Exit 1.
- **Reihenfolge der Prüfungen:** erst Konfiguration und Pfad (Punkte 2 und 3, im gemeinsamen Pfadlauf `src/export_path.cpp`, den die Tabelle in PR C wiederverwendet), dann die Systemdaten von Punkt 4 (Umgebung, Grenzen, Systemapertur), dann Gläser und Formen. Gemeldet wird der erste Fehler.
- **`refract` an Blende und Detektor** (Entscheidung des Maintainers, 2026-11-09): Ein explizites `refract` an einer Blende oder einem Detektor gilt wie `transmit` und wird exportiert. Das erweitert Punkt 3.
  - **Grund:** `refract` ist die Standardart eines Ereignisses ohne `kind`, und an einem Element ohne Material behält es das Medium wie `transmit` (`compile()`). Nach dem Wortlaut von Punkt 3 wären Pfade wie in `r2/ideal_lens` `export.event_unsupported` gewesen.
  - **Grenze:** Andere Arten bleiben `export.event_unsupported`, z. B. `reflect` an einer Blende. Am dünnen Element bleibt es bei `transmit`; die ideale Linse verlangt es dort ohnehin (`paths.ideal_lens_event`).
- **Aus dem Review von PR B:**
  - Ein Katalogname mit Leerzeichen (ein Katalog aus der Datei `MY CAT.agf` ohne Alias) gibt `export.material_unsupported`; der Import teilte die `GCAT`-Zeile am Leerzeichen.
  - Ein dünnes Element ohne Apertur und ohne ideale Linse gibt `export.surface_unsupported`. Der Import ließe die Luft-Luft-Fläche weg (ADR 0044, Punkt 5), mit Brechkraft auch mit `zmx.surface_dropped`.
  - Eine Krümmung 1/R, die nicht endlich ist (|R| unter etwa 5,6·10⁻³⁰⁹ mm), gibt `export.surface_unsupported`.
- **Was außer den Formen aus Punkt 1 anders zurückkommt**, mit derselben Optik: eine `plate` als `lens`, eine Blende auf der Fläche eines dünnen Elements als `stop`-Element, eine `odd_asphere` mit c = 0 und allen Termen 0 als `plane`, ein Name ohne Leerzeichen am Anfang und Ende (der Import schneidet sie ab).
- **Form der Datei**, wo Punkt 4 sie offenlässt:
  - `VERS 60801 67 21410` wie die Testdateien von `make_zmx_cases.py`;
  - `XFLN`, `YFLN` und `FWGN` mit genau so vielen Werten wie Feldern, `WAVM` nur für die Wellenlängen des Systems;
  - `GLAS <name> 0`, ohne die Katalogdaten, die OpticStudio dahinter schreibt;
  - `DIAM 0 0` an jeder Fläche außer der Blende, die Fläche 0 mit `TYPE STANDARD` und `CURV 0`;
  - `PARM 1 0` bis `PARM 8` bei `EVENASPH`, auch für Nullen.
  Ob OpticStudio diese Form liest, bleibt nach F7 offen.
- **Kanonische Form (Punkt 6) im Export:** Sie entscheidet nur, ob die Dicke das t der Pose oder eine Differenz der globalen z ist. Die Prüfung ist strenger als nötig (die erste Fläche jedes Elements ohne eigene Pose), denn beide Wege geben bis auf Rundung dieselbe Geometrie.
- **Abnahme 3, Stand:** Von 51 Referenzsystemen gehen 8 durch Export und Import (`m0/singlet`, `m2/achromat`, `m2/cooke_triplet_surface_stop`, `m2/paraboloid_stop`, `m6/paraboloid_f10`, `m6/paraboloid_f50`, `m7/achromat_tolerances`, `r2/ideal_lens`). Die übrigen scheitern mit einem `export.*`-Code; die häufigste Ursache ist `VACUUM` als Umgebung (`export.environment_unsupported`, 17 Systeme).
- **Lokaler Lauf am OISC-Korpus (nicht im Repository):** Von den 7 Dateien, die der Import abbildet, sind 5 koaxial. Sie kommen über Import, Export und erneuten Import mit bitgleicher f′_R und BFL zurück (die „400 mm Lens“ und ihre Varianten). Die beiden Parabeldateien enthalten Koordinatensprünge und geben `export.not_coaxial`.

## Nachtrag (#318, PR C, 2026-11-09): Umsetzung der Flächentabelle

**Entscheidungen des Maintainers** zum Vorschlag für PR C (2026-11-09, in der Sitzung), jeweils der Empfehlung folgend:
- **G1:** Eine `odd_asphere` hat in der Tabelle keine Spalte, auch mit c = 0: `export.surface_unsupported`. Die Tabelle hält nur `plane`, `conic` und `even_asphere` (Punkt 7). Die drei Asphärenfälle des ZMX-Imports gehen deshalb nicht durch die Tabelle.
- **G2:** Verlässt ein expliziter Pfad ein Element und betritt es später wieder, wäre das Element in der Tabelle zweimal da (`table.duplicate` beim Lesen). Beim Schreiben ist das `export.event_unsupported`, ohne neuen Code.
- **G3:** `TableError::line()` ist die physische Zeile, in der das Feld beginnt (die Kopfzeile ist Zeile 1; ein Feld in Anführungszeichen mit Zeilenumbruch zählt ab seiner ersten Zeile). `column()` ist die Nummer des Feldes im Satz, nicht die Zeichenposition. 0 und 0 gelten für die ganze Datei.
- **G4:** Die Objektzeile enthält nur `row`, `thickness` und `material`; jedes andere gesetzte Feld ist `table.value`. In der letzten Flächenzeile wird `thickness` leer geschrieben; gelesen werden leer und eine Zahl.
- **G5:** `stop` = `true` an einer Zeile der Art `stop` ergibt das Blendenelement, an jeder anderen Zeile `aperture.stop`. Ein zweites `true` oder ein anderer Wert ist `table.value`.
- **G6:** ein PR für Leser, Schreiber, CLI und Doku.

**Festlegungen, wo Punkt 7 sie offenlässt:**
- **Spalten:** Alle Spalten von Punkt 7 sind Pflicht; eine fehlende ist `table.column` mit Zeile 0. Eine Spalte, die später hinzukommt, wird beim Lesen optional sein, damit ältere Tabellen lesbar bleiben.
- **Feldzahl:** Eine Zeile mit anderer Feldzahl als die Kopfzeile ist `table.parse` an der Stelle des ersten überzähligen bzw. fehlenden Feldes.
- **Material in Linsen und Platten:** An jeder inneren Fläche ist `material` gesetzt, an der letzten leer (zurück in die Umgebung); sonst `table.value`. Sind die Materialien einer Linse gleich, wird es `material`, sonst `segment_materials`.
- **Spiegel** werden beim Einlesen `ideal_mirror`, wie beim ZMX-Import. Ein Spiegel mit `fresnel` (idealer Leiter, ADR 0034, Punkt 7) kommt deshalb als `ideal_mirror` zurück.
- **Nur Werte:** `variable`, `min` und `max` der Parameter im Baum, `pivot` und `order` der Posen und ein ausdrücklich gesetztes Objektmedium gleich der Umgebung entfallen ohne Warnung; die Geometrie bleibt. Die Bitgleichheit von Punkt 7 gilt für Systeme ohne sie.
- **Innere Segmente aus dem Umgebungsmedium** (ein Luftspalt in einem Kittglied, Review von PR C): Die Tabelle schreibt an jeder inneren Fläche einer Linse oder Platte das Material des Segments, auch wenn es das Umgebungsmedium ist; sonst läse der eigene Leser die Tabelle nicht.
- **Zeilenende:** Eine leere Zeile am Ende der Datei ist kein Satz (Texteditoren hängen oft eine an).
- **Asphärenkoeffizienten:** Gelesen wird die Liste bis zum letzten gesetzten Feld. Nullen am Ende der Liste des Modells gehen verloren; die Fläche ist dieselbe.
- **Basissystem:** Gebundene Parameter werden vor dem Verwerfen der Parametertabelle mit der Konfiguration 0 aufgelöst (`resolve_parameters`), damit z. B. eine gebundene EPD ihren Wert behält. Der Pfad behält den Namen des ersten Pfades des Basissystems. `object.reference` entfällt mit dem Objekt, ohne Warnung.
- **Zahlen:** Schreiben und Lesen teilen sich mit dem ZMX-Import und -Export die Hilfen in `src/numbers.hpp` (`std::to_chars` ohne Format, `std::from_chars`). Der Import liest damit wie bisher, nur ohne eigene Kopie.
- **CLI:** Das Format folgt aus der Endung, ohne Groß- und Kleinschreibung. `rtt import` verlangt `--base` genau für `.csv`; sonst ist der Aufruf falsch (Exit 2).

## Nachtrag (#368, 2026-11-10): `odd_asphere` als `ODDASPHE`

Vorschlag in #368. Er kehrt den Import von `ODDASPHE` um (ADR 0044, Nachtrag #360 PR A) und erweitert Punkt 4. Quelle wie dort: [UG] „Odd Asphere“ (Zeile „ZMX-Import: `ODDASPHE` und `TOROIDAL`“ in `docs/quellen.md`); keine neue Quelle.

- **Abbildung:** Eine `odd_asphere` wird `TYPE ODDASPHE` mit `CURV` c, `CONI` k und `PARM 1` … `PARM 8` = A1 … A8.
  - Die Datei hat `UNIT MM`, also ist β_n = A_n ohne Umrechnung.
  - Wie bei `EVENASPH` stehen alle acht `PARM`-Zeilen da, auch für Nullen (Nachtrag PR B).
  - `CURV` ist c selbst, nicht 1/R; die Krümmung kommt also bitgleich zurück.
- **Wahl der Form (Entscheidung des Maintainers, 2026-11-10, in der Sitzung): `EVENASPH` hat Vorrang.**
  - Nimmt `EVENASPH` die Fläche auf (c = 0, A1 = A2 = A3 = 0, nur gerade Terme bis A16), bleibt es bei `EVENASPH` wie bisher.
  - `ODDASPHE` schreibt der Export nur für die übrigen Flächen mit Termen höchstens bis A8: c ≠ 0, ein Term A1, A2 oder A3 oder ein ungerader Term.
  - **Gründe:** Bisherige Exporte bleiben bytegleich, und `EVENASPH` ist der verbreitetere Typ. Beide Formen kommen beim Import als dieselbe `odd_asphere` zurück.
  - **Folge:** Die Form der Datei hängt von den Werten ab, nicht nur von der Art. Gehen die ungeraden Terme einer Fläche mit c = 0 auf 0, wechselt sie zu `EVENASPH`.
  - **Warum c ≠ 0 nie `EVENASPH`:** Der Import liest `EVENASPH` mit c ≠ 0 als `even_asphere` (ADR 0044, Punkt 6); die Art wechselte.
- **Fehler:** Nimmt keine der beiden Formen die Fläche auf, bleibt es `export.surface_unsupported`, ohne neuen Code. Das ist ein Koeffizient ab A9 ≠ 0 zusammen mit c ≠ 0, einem Term A1 … A3 oder einem ungeraden Term, oder ein Term über A16.
- **Gespiegelte Fläche (Achse −e_z):** unverändert nach Punkt 2, c → −c und A_n → −A_n, die Konik bleibt.
- **Was anders zurückkommt**, mit derselben Fläche (Ergänzung zu Punkt 1 und zum Nachtrag PR B):
  - c = 0 und k ≠ 0: k = 0, wie bisher über `EVENASPH`; der Import verwirft die Konik bei c = 0;
  - c ≠ 0 und alle Terme 0: `conic` mit R = 1/c, denn der Import liest `ODDASPHE` ohne β wie `STANDARD`;
  - Nullen am Ende der Koeffizientenliste entfallen.
- **Flächentabelle:** bleibt ohne `odd_asphere` (G1).
- **Abnahme:**
  - Die Fälle `oddasph`, `oddasph_in` und `oddasph_cone` gehen über Import, Export und erneuten Import bitgleich zurück; R der `STANDARD`-Flächen und die Wellenlängen auf 10⁻¹⁵ relativ wie in Abnahme 2.
  - Ein Singulett mit allen acht Koeffizienten gegen von Hand geschriebene Werte, die Wahl der Form an sieben Fällen, die gespiegelte Fläche und die Fehlerfälle.
  - **Inhaltswächter:** Die Rundreise hat genau eine `odd_asphere` mit einem ungeraden Term, und die Strahlen kommen an.
- **Regel 2:** Der Fehlerfall in `test_zmx_export.cpp`, der eine `odd_asphere` mit c ≠ 0 und nur A4 als Beispiel für `export.surface_unsupported` nahm, wird jetzt `ODDASPHE`. Er nimmt stattdessen c ≠ 0 mit A10 ≠ 0 (Freigabe des Maintainers im PR erbeten).
