# ADR 0020: Gemeinsamer strikter JSON-Parser in der Basisschicht

**Status:** angenommen (2026-10-05)

## Kontext

Zwei Bibliotheken lesen JSON mit nlohmann-json: `rtt-io` (Systemdateien, ADR 0008) und
`rtt-coating` (Coating-Kataloge, ADR 0019). nlohmann-json übernimmt bei doppelten Schlüsseln
stillschweigend den letzten Wert; aus `{"thickness_um": -1, "thickness_um": 0.1}` wird 0,1, und
`rtt validate` akzeptiert eine Datei mit zwei verschiedenen `schema_version`. Außerdem meldet
nlohmann-json eine Zahl jenseits des `double`-Bereichs (z. B. `1e400`) als `out_of_range`, die
`rtt-io` nicht als `ParseError` übersetzte. Beide Parser sollen das einheitlich behandeln (#68).
Wegen der Schichtregel dürfen sich `rtt-io` (Schnittstellen) und `rtt-coating` (Physik)
gegenseitig nicht verwenden. Der Koordinator hat im Auftrag des Maintainers entschieden.

## Entscheidung

1. **Neue Bibliothek `rtt-json`** in der Schicht Basis, header-only (CMake-Target `INTERFACE`,
   `rtt::json`), einzige Abhängigkeit nlohmann-json (schon in `vcpkg.json`). `rtt-math` bleibt
   unverändert.
2. **Inhalt:** `rtt::json::parse_strict(text) -> nlohmann::json` und
   `rtt::json::StrictParseError { pointer, message }`, dazu `pointer_token` (RFC 6901). Fehler:
   doppelter Schlüssel auf jeder Ebene mit dem JSON-Pointer des zweiten Vorkommens
   (`<pointer>: duplicate key '<key>'`), Syntaxfehler und Zahlen-Overflow mit leerem Pointer
   (`invalid JSON: …`). Gleiche Schlüssel in verschiedenen Objekten sind erlaubt.
3. **Mechanismus:** der öffentliche `parser_callback_t` von nlohmann-json mit einem Stapel je
   offenem Objekt (gesehene Schlüssel) bzw. Array (Elementindex); keine internen `detail`-Klassen.
   Das Dokument selbst baut nlohmann-json wie bisher.
4. **Verwendung:** `rtt-io` und `rtt-coating` linken `rtt::json` PRIVATE und übersetzen
   `StrictParseError` in ihre Fehlertypen (`ParseError` bzw. `CoatingCatalogError` mit Datei).
   Python erhält den Pointer über die bestehende Übersetzung (`rt.ParseError.pointer`).
   Das Schreiben ist nicht betroffen; die Ausgabe hat nie doppelte Schlüssel.

## Verworfen

- **Hilfsfunktion in beiden Parsern duplizieren:** keine Architekturänderung, aber zwei Kopien,
  die auseinanderlaufen können; die Vorgabe „einheitlich“ wäre nur durch gleiche Tests gesichert.
- **In `rtt-math`:** `rtt-math` ist Mathematik mit Eigen; nlohmann-json würde dort für alle
  Bibliotheken sichtbar.
- **SAX-Parser oder `detail`-Klassen von nlohmann-json:** mehr Code und keine stabile API; der
  Callback reicht.

## Folgen

- Weitere JSON-Leser (z. B. künftige Formate) nutzen `parse_strict`.
- Die Schicht Basis enthält zwei Bibliotheken; `docs/architecture.md` zählt 16 Bibliotheken bzw.
  Programme.
