# ADR 0044: ZMX-Import des sequenziellen Teils (M8 I1)

**Status:** angenommen (Maintainer, 2026-11-07, #355)

## Kontext

I1 (#317) bringt den Import von OpticStudio-Dateien (`.zmx`) in das Modell, als Bibliotheksfunktion und als `rtt import`.

- **Vorschlag:** #317, v1 (Kommentar 6547378083, 2026-10-31) und Nachtrag v2 (Kommentar 6705591659, 2026-11-07).
- **Entscheidungen:**
  - Der Maintainer hat am 2026-10-31 Frage 3 entschieden (Blendenradius 1,1 · `DIAM` bei `ENPD`/`FNUM`) und Frage 4 (PR A vor S1–S3).
  - Am 2026-11-07 hat er allen Empfehlungen aus v2 zugestimmt, Fragen 1 bis 4 (Kommentar 6705798472 auf #317).
  - **Abweichungen dieses ADR von v2**, beim Annehmen mitbeschlossen: `EVENASPH` mit c = 0 wird `odd_asphere` (Punkt 6); die Aufteilung der PRs (Folgen, die Flächentypen aus S1–S3 in einem eigenen Issue); die Codes `zmx.invalid_result`, `zmx.aperture_decenter` und die Schutzregeln aus den Punkten 4, 5 und 8, die erst das Review dieses ADR ergeben hat; Flächen-IDs nur `S<n>` statt `STO`/`IMG` aus v1.
- **Testkorpus:** 54 ZMX-Dateien des OISC-Kurses (VERS 60801), lokal ausgewertet. Die Seite nennt keine Lizenz, deshalb kommen die Dateien nicht ins Repository (Entscheidung des Maintainers, 2026-11-06). Die Repo-Tests nutzen eigene, handgeschriebene Dateien.

**Quellen** (Zeilen in `docs/quellen.md`):

Ansys veröffentlicht keine Beschreibung der ZMX-Schlüsselwörter. Die Datei-Typen-Seite nennt ZMX nur „a text file which contains the complete description of the lens“. Deshalb gibt es zwei Arten von Quellen:

- **[UG] Bedeutung der Größen:** OpticStudio User Guide, Release 2025 R2 (ansyshelp.ansys.com). Dieselbe Quellenart wie bei AGF und der Apodisation. Gelesen wurden die Seiten:
  - „Standard“, „Even Asphere“, „Coordinate Break“;
  - „Aperture Type“, „Field Type“, „Units“, „Thickness“, „Material“, „Wavelengths“;
  - „Using Model Glasses“, „Clear Semi-Diameter or Semi-Diameter“.

  Die Gleichungen dort sind Grafiken ohne Nummer.
- **[ZR] Zuordnung Schlüsselwort → Größe:** nur aus Lesern mit freier Lizenz, im Quelltext gelesen:
  - optiland (MIT, `optiland/fileio/zemax/reader/parser.py`);
  - ray-optics (BSD-3, `rayoptics/zemax/zmxread.py`);
  - CEO (Zlib, Zemax-Leser, Klasse `ZemaxModel`).

  Leser unter GPL oder LGPL (rayopt, KrakenOS) wurden nicht geöffnet. Was nur ein Leser oder nur der Korpus belegt, ist unten als **Lesart** markiert.

**Bestand im Code (main 9eae803f):**

- Schema 0.9.0 mit allen Basistypen aus S1 und S2.
- Flächenblende `aperture.stop` (ADR 0039), `object_na` mit `reading` (ADR 0040), `object.medium` (ADR 0037), `object.reference` (ADR 0038), relative Posen (ADR 0028).
- AGF-Leser mit Erkennung von UTF-16 (`rtt-material`).
- `rtt::compile::line_vacuum_wavelength_um` löst λ_vac = λ_Luft · n_Luft(λ_vac) als Fixpunkt (ADR 0036).

## Entscheidung

### 1. API und CLI

Neuer Header `rtt/io/zmx.hpp` in `rtt-io`. Die Bibliothek liegt in der Schicht Schnittstellen und darf `rtt-material` und `rtt-compile` nutzen.

```cpp
struct ZmxImport { model::System system; std::vector<model::Diagnostic> warnings; };
ZmxImport import_zmx(std::string_view bytes, const material::MaterialLibrary& lib);
ZmxImport load_zmx(const std::filesystem::path& file, const material::MaterialLibrary& lib);
class ZmxError : public std::runtime_error { /* code(), line(); line 1-based, 0 = whole file */ };
```

- Die Bibliothek löst die Glasnamen auf (Punkt 7).
- Das Ergebnis läuft vor der Rückgabe durch `validate` und `compile`. `compile` prüft, was `validate` nicht prüft (Formel und Wellenlängenbereich der Gläser). Ein Fehler aus `validate` oder ein `CompileError` wird `ZmxError` mit dem Code `zmx.invalid_result`, Zeile 0 und der Meldung des Originals. Warnungen aus `validate` und `compile` kommen mit ihren eigenen Codes in `ZmxImport::warnings`.
- **CLI:** `rtt import <datei.zmx> <ausgabe.rtt.json> --catalog <agf>...`.
  - Die Ausgabe wird kanonisch geschrieben (`save_system`).
  - Warnungen gehen wie bei `validate` nach stderr.
  - Exit-Codes wie bisher: 0 (gut), 1 (Fehler im Import, auch eine fehlende oder unlesbare Datei), 2 (Aufruf falsch).

### 2. Lesen

- **Kodierung:** Ein BOM `FF FE` heißt UTF-16 LE, sonst ASCII bzw. UTF-8; die Erkennung kommt aus dem AGF-Leser. Ein BOM `FE FF` (UTF-16 BE) ist der Fehler `zmx.encoding_unsupported`.
- **Zahlen** mit `std::from_chars`, unabhängig von der Locale. `INFINITY` nur bei `DISZ`.
- **Zeilen:** Eine Zeile beginnt mit einem Schlüsselwort aus vier Zeichen. Eingerückte Zeilen gehören zur letzten `SURF`-Zeile.
- `MODE` muss `SEQ` sein, sonst `zmx.mode_unsupported`.
- **Blöcke nach den Flächen** (Lesart, belegt nur am Korpus): In allen 54 Dateien folgen auf den letzten Flächenblock:
  - der Merit-Editor (Operandenzeilen wie `EFFL`, `TRAC`, `OPDX`, `BLNK`, `DMFS`);
  - die `TOL`-Zeilen, darunter `TCMM`;
  - ab `MNUM` der Editor der Konfigurationen bis zum Dateiende.

  Merit- und Toleranzblock werden als Ganzes still übersprungen. Fehlt `TOL` oder `MNUM`, läuft der Block bis zum nächsten vorhandenen bzw. bis zum Dateiende. Den Konfigurationsblock regelt Punkt 9.
- **Unbekanntes:**
  - Eine feste Liste reiner Anzeige- und Notizdaten wird still übergangen, z. B. `VERS`, `NAME`, `NOTE`, `COMM`, `HIDE`, `SLAB`, `POPS`, `MIRR` (nur Zeichnung), `MAZH`, `EDGE`, `MEMA`, `PUPD`, `PICB`, `ROPD`, `COAT`, `COFN`, `POLS`, `NSCD`, `GFAC`, `GLRS`, `GSTD`, `RAIM`, `PUSH`, `SDMA`.
  - Jedes andere unbekannte Schlüsselwort gibt die Warnung `zmx.keyword_ignored`, einmal je Schlüsselwort mit der Zahl der Vorkommen und der ersten Zeile.
  - Alles, was die Optik ändert und hier nicht abgebildet wird, ist ein Fehler (Punkte 4 bis 10).

### 3. Einheiten

- `UNIT` MM, CM, IN, METER gibt den Faktor s = 1, 10, 25,4 bzw. 1000 mm je Linseneinheit; sonst `zmx.unit_unsupported`. [UG] „Units“ nennt die vier Einheiten („millimeters, centimeters, inches, or meters“); die Kürzel in der Datei sind eine Lesart aus [ZR] (MM: CEO, ray-optics; IN: ray-optics; METER: CEO) und dem Korpus (alle 54 Dateien `UNIT MM`); CM belegt kein Leser und ist nach den vier Einheiten des User Guide angenommen.
- **Skaliert** werden Dicken, Objektabstand, Objekt- und Bildhöhen, `ENPD`, Halbdurchmesser und Aperturen.
- **Krümmung:** R = 1/(c/s). In mm ist das R = 1/c.
- **Asphärenkoeffizienten:** α_i zu r^(2i) hat die Einheit L^(1−2i), also α_i,mm = α_i · s^(1−2i).
  - Gerechnet wird durch fortgesetzte Multiplikation mit 1/s in fester Reihenfolge, ohne `pow`, denn `pow` hängt an der libm.
  - In mm gehen die Koeffizienten unverändert durch.
- Winkel und Wellenlängen (immer µm, [UG] „Units“) bleiben unverändert.

### 4. Systemdaten

| ZMX | Modell |
|---|---|
| `WAVM` (neu) bzw. `WAVL`/`WWGT` (alt), aktiv sind die ersten n nach `FTYP` Feld 4; `PWAV` | `wavelengths`, auf Vakuum umgerechnet (unten) |
| `ENVD T p f` | nur T = 20 °C, p = 1 atm, sonst `zmx.environment_unsupported`; f unten |
| `ENPD` | `epd` |
| `FNUM v 0` (Image Space F/#) | `image_fnumber` = v / n_Luft (unten) |
| `FLOA` | `stop_size` |
| `OBNA v 0` (Object Space NA) | `object_na` = n_Luft · v mit `reading = real` (unten) |
| `FNUM v 1`, `OBNA v 1` | `zmx.aperture_unsupported` |
| `FTYP` 0 / 1 / 2 | `angle_deg` / `object_height` / `paraxial_image_height` |
| `FTYP` 3 (Real Image Height), 4 (Theodolite Angle) | `zmx.field_unsupported` |
| `FTYP` Stelle 2 = 1 (objektseitig telezentrisch, Lesart optiland) | `zmx.aperture_unsupported`: Das Modell hat keinen solchen Schalter; Telezentrie folgt bei uns aus der Lage der Blende |
| `FTYP` Stelle 7 = 1 (Afocal Image Space, Lesart optiland) | ignoriert mit der Warnung `zmx.afocal_image_space`: In OpticStudio ändert der Schalter nur die Einheiten der Analysen, nicht den Strahlverlauf (Lesart, im Korpus 4 Dateien) |
| `XFLN`/`YFLN` (bzw. `XFLD`/`YFLD`), `FWGN` (bzw. `FWGT`) | `fields`; Werte absolut in der Einheit des Feldtyps, Längen skaliert |
| `VDXN`, `VDYN`, `VCXN`, `VCYN`, `VANN` ≠ 0 | `zmx.vignetting_unsupported` |

- **Codes von `FTYP`:** Field Type 0 bis 4 nach [UG] „Field Type“. Vorzeichen: „Positive field angles imply positive slope for the ray in that direction“ ([UG] „Field Type“), wie die Feldkonvention in `docs/architecture.md`. Dass ein Feld (θx, θy) die Richtung ∝ (tan θx, tan θy, 1) meint, ist eine Lesart. Die Stellen 3 und 4 von `FTYP` als Anzahl der Felder und Wellenlängen sind eine Lesart aus [ZR] (optiland, CEO).
- **Zweites Feld von `FNUM` und `OBNA`:** eine Lesart aus [ZR] (optiland): 0 = Image Space F/# bzw. NA, 1 = Paraxial Working F/# bzw. Object Cone Angle.
- **Wellenlängen Luft → Vakuum:** [UG] „Wavelengths“: „Wavelength data are always measured in micrometers referenced to "air" at the current system temperature and pressure.“
  - λ_vac = λ_Luft · n_Luft(λ_vac) nach Ciddor bei 20 °C und 1 atm, gelöst über den Fixpunkt `line_vacuum_wavelength_um`.
  - Ein einzelner Schritt mit n_Luft(λ_Luft) läge relativ 2,5·10⁻⁹ (d-Linie) bis 7,3·10⁻⁹ (0,365 µm) daneben.
  - ADR 0036 hat das für die Fraunhofer-Linien entschieden; dieses ADR übernimmt es für die Systemwellenlängen.
- **Indizes relativ zu Luft:** OpticStudio rechnet mit Indizes relativ zu Luft, Raytatouille mit absoluten. Die Umrechnung im AGF-Leser folgt „Index of Refraction Computation“ (`docs/quellen.md`, Zeile „Umrechnung von Katalogdaten“): λ_rel = λ_vac / n_Luft(λ_vac, T_ref, 1 atm), n_abs = n_rel · n_Luft + Δn_abs.
  - OpticStudio nimmt für n_Luft die Formel nach Kohlrausch, Raytatouille Ciddor. Bei T_ref = 20 °C und 1 atm geht das nicht in die Strahlen ein: Mit λ_vac aus dem Ciddor-Fixpunkt ist λ_rel wieder die Luftwellenlänge der Datei, also wertet `rtt-material` jedes Glas bei der Wellenlänge aus, die OpticStudio nimmt (bis auf den Rest des Fixpunkts, etwa 10⁻¹⁶ relativ). Alle Index-Verhältnisse und damit die Strahlen sind gleich. Nur der gemeinsame Faktor n_Luft hängt an der Formel; er geht unten konsequent mit Ciddor ein.
  - Werden alle Indizes mit demselben n_Luft multipliziert, bleibt der Strahlverlauf gleich. Nur die Brechkraft skaliert: unsere `efl` ist die Zemax-EFL / n_Luft, unsere `rear_focal_length` (|n′|/Φ) bei Bildraum Luft gleich der Zemax-EFL. BFL und alle Lagen sind in beiden Programmen derselbe Abstand.
  - **F/#:** Bei uns gilt EPD = |EFL|/F# mit der absoluten EFL (architecture.md, Engine 1). Damit die EPD dieselbe wird, teilt der Import F# durch n_Luft.
  - **NA:** [UG] „Aperture Type“, Code 2: „The numerical aperture (NA = n sin θm) of the marginal ray in object space, where n is the index of refraction of the object.“ n ist dort relativ zu Luft, ADR 0040 rechnet mit dem absoluten n_ref, also NA_rtt = n_Luft · NA_Zemax. Die Lesart „real“ folgt aus „of the marginal ray“.
  - n_Luft ist überall n_Luft(λ_vac,ref, 20 °C, 1 atm) nach Ciddor, mit der Vakuumwellenlänge der Referenz (`PWAV`); bei ihr rechnen beide Programme die paraxialen Größen.
  - Das gilt genau, wenn jedes verwendete Glas T_ref = 20 °C hat (dann ist Δn_abs = 0 und der AGF-Leser rechnet n_abs = n_rel · n_Luft(λ_vac, 20 °C, 1 atm)).
- **Umgebung:** Der Import setzt `environment` ausdrücklich auf `AIR` bei 20 °C und 1 atm und verlässt sich nicht auf die Vorgaben des Modells.
- **Drittes Feld von `ENVD`:** wird ignoriert, wenn jedes verwendete Glas T_ref = 20 °C hat; dann ändert eine Anpassung an die Umgebung keine Brechzahl. Sonst gibt es die Warnung `zmx.glass_reference_temperature`. Kein Leser belegt die Bedeutung des Felds.

### 5. Flächen → Baum

- **Ursprung:** der Scheitel von Zemax-Fläche 1. Entfällt Fläche 1 als Dummy, liegt das erste Element bei z = Summe der entfallenen Dicken.
- **Objekt:**
  - Fläche 0 mit `DISZ INFINITY` → `at_infinity`. Glas auf Fläche 0 ist dann der Fehler `zmx.object_medium_infinite`; ohne ihn griffe `object.medium_infinite` aus ADR 0037 ohne Zeile.
  - Sonst `distance` = DISZ₀ · s, bezogen auf den Ursprung; das Glas von Fläche 0 wird `object.medium` (ADR 0037). Fläche 1 bricht dann vom Objektmedium aus (`medium_before`, ADR 0037). Sie muss eine Linse beginnen (Glas dahinter); führt sie in Luft, ist das der Fehler `zmx.object_medium_unsupported`, denn ein Element mit einer brechenden Fläche zwischen Objektmedium und Luft gibt es nicht.
  - `object.reference` (ADR 0038) wird nicht genutzt: Der Ursprung liegt im Scheitel von Fläche 1, so geht DISZ₀ bitgleich durch.
- **Gruppierung** nach dem Medium hinter jeder Fläche:
  - Eine Fläche mit Luft davor und Glas dahinter beginnt eine `lens`. Glas auf Glas gibt eine Materialliste (Kittglied, ADR 0017). Luft dahinter schließt die Linse.
  - Leeres Glas ist das Umgebungsmedium `AIR`.
- **Spiegel:** `GLAS MIRROR` in Luft → `mirror` ohne Material mit `ideal_mirror`.
  - Das ist eine gewollte Abweichung. [UG] „Material“: Ohne Coating nimmt OpticStudio Aluminium mit 0,7 − 7,0i. Die Geometrie ist gleich, Reflexionsgrad und Polarisation nicht.
  - Ein Spiegel im Glas (Mangin) ist in I1 der Fehler `zmx.mirror_in_glass`.
- **Glas vor der Bildfläche:** Fehler `zmx.image_in_glass`, denn zwischen Elementen liegt bei uns immer das Umgebungsmedium.
- **Lagen** über relative Posen (ADR 0028):
  - Jedes Element und jede innere Fläche liegt `relative_to_preceding` mit z = DISZ · s der vorigen Fläche; nur das erste Element liegt absolut. So ist jede Dicke genau ein Param, wie in der Datei (hilft dem Export in I2). Ausnahme: Hinter entfallenen Dummy-Flächen ist z die Summe der Dicken, von vorn nach hinten addiert.
  - Negative Dicken nach Spiegeln werden mit Vorzeichen übernommen ([UG] „Thickness“: „Thicknesses always change sign after a mirror.“). Nachgerechnet: CURV −0,005, DISZ −100 gibt R = −200 und den Detektor bei z = −100, wie `tests/reference/m1/paraboloid_mirror.rtt.json`.
- **Bild:** `detector` mit der Form der Bildfläche.
- **Luft-Luft-Flächen** (Luft auf beiden Seiten):
  - **Ohne Apertur und ohne Blende** entfallen sie, ihre Dicke geht in die nächste Pose ein. Eine solche Fläche mit Brechkraft gibt die Warnung `zmx.surface_dropped`; das Weglassen ist exakt, weil sie keinen Strahl ändert.
  - **Mit Apertur** (`CLAP` oder gültiges `FLAP`, Punkt 8) werden sie ein `thin_element` mit ihrer Form und der Apertur, ohne Material. Der automatische Pfad gibt dort `Transmit`; Transmit an einer Fresnel-Fläche ist eine reine Durchgangsfläche (`apply_event.hpp`). `validate` erlaubt dort auch eine gekrümmte Form.
  - **Als Blende** (Punkt 8) werden sie ein `stop`-Element mit ihrer Form, auch wenn sie ein `CLAP` oder `FLAP` tragen; die Blende geht dem `thin_element` vor.
- **Namen und IDs:**
  - Elemente heißen `L1`, `L2`, … (Linsen), `M1`, … (Spiegel), `T1`, … (dünne Elemente), dazu `stop` und `image`. Die Namen sind eindeutig und nicht leer.
  - Flächen-IDs sind `S<n>` nach der Zemax-Nummer; so passen Fehlermeldungen und Datei zusammen.
  - Pfad `events: auto`.

### 6. Formen

- **`STANDARD`** ([UG] „Standard“): c = 0 → `plane` (ein `CONI` ist dann wirkungslos und entfällt), sonst `conic` mit R = 1/c und k aus `CONI`.
- **`EVENASPH`** ([UG] „Even Asphere“, Parameter 1–8 = α1 … α8 zu r², r⁴, …, r¹⁶):
  - c ≠ 0 und α1 = 0 → `even_asphere` mit R = 1/c, k und `coefficients` = α2 … α8. Unser Koeffizient [0] ist A4 = α2.
  - c = 0 und α1 = 0 → `odd_asphere` (ADR 0043) mit `curvature` = 0, `conic` = 0 (bei c = 0 wirkungslos, so entfällt die Warnung `shape.conic_without_curvature`) und `coefficients` A1 = 0, A2 = 0, A3 = 0, A4 = α2, A5 = 0, A6 = α3, … Die Abbildung ist exakt, auch paraxial: Die Scheitelkrümmung ist in beiden Programmen 0. v1 sah hier den Fehler „c = 0 nicht darstellbar“ vor; seit S1 ist er unnötig.
  - α1 ≠ 0 → Fehler `zmx.asphere_r2` wie in v1. Geometrisch wäre `odd_asphere` mit A2 = α1 exakt, aber unsere Paraxialrechnung nimmt die Scheitelkrümmung c + 2α1 (ADR 0041), und ob OpticStudio α1 paraxial berücksichtigt, belegt keine Quelle. Davon hingen `FNUM`, `FTYP 2` und die Pupillenlage ab.
  - Abschließende Nullen werden abgeschnitten. Sind alle α = 0, gilt die Regel für `STANDARD`.
- **Jeder andere `TYPE`** → `zmx.surface_unsupported` mit Zeile und Typ.
  - `COORDBRK`, `TILTSURF` und `PARAXIAL` kommen in PR C.
  - Die Typen aus S1–S3 (`ODDASPHE`, `TOROIDAL`, `BICONICX`, Q-Typen, Zernike) kommen in einem eigenen Issue nach S3. Jeder nur, wenn ein Leser mit freier Lizenz oder [UG] die Reihenfolge der `PARM`-Felder belegt.
- Das Vorzeichen des Radius folgt der Konvention aus `docs/architecture.md` (R > 0: Krümmungsmittelpunkt bei +z) und ist dasselbe wie in OpticStudio.

### 7. Gläser

- **Auflösung:** `GLAS name` über die `GCAT`-Reihenfolge.
  - Der Katalogname wird ohne Rücksicht auf Groß- und Kleinschreibung verglichen (`GCAT SCHOTT` findet `schott.agf`), der Glasname genau.
  - Der erste Katalog, dessen `resolve` das Glas liefert, gewinnt → `KATALOG:NAME`.
  - Nicht gefunden → `zmx.glass_unknown` mit Zeile und den durchsuchten Katalogen.
- **Modellgläser** → `zmx.model_glass`:
  - Feld 2 der `GLAS`-Zeile = 1 oder der Name `___BLANK` (Lesart aus [ZR], optiland `_read_glass`);
  - eine MIL-Nummer als Name, also sechs Ziffern oder die Form `517.642` (optiland).

  Begründung: Zemax legt die Dispersionsformel der Modellgläser nicht offen ([UG] „Using Model Glasses“: „a formula based upon the typical dispersion of standard glasses“). Jeder Ersatz wäre ein anderes Glas.
- **Andere Werte von Feld 2** werden ignoriert. Im Korpus steht 3 an echten Katalognamen wie `LASFN30 3` im Cooke-Triplet.
- **nd und νd der `GLAS`-Zeile** werden nicht ausgewertet. Im Korpus sind sie fast nie die des Glases: Platzhalter 1,5/40 oder 0/0, oder die Werte eines anderen Glases (SF10 mit den Daten von F2); nur etwa 7 von 55 Zeilen passen.
- **Keine Ersetzung** von Altgläsern (BK7 → N-BK7): Das wäre ein anderes Glas.

### 8. Aperturen und Blende

**`DIAM v f s …`** (Lesart: f = 1 fixiert, sonst automatisch nach optiland `_read_diameter`; f = 2 als Pickup und das Feld s nur aus dem Korpus):
- Feld f: 0 = automatisch, 1 = fixiert („U“), 2 = Pickup von Fläche s. Der Wert v ist in allen Fällen der aufgelöste Halbdurchmesser.
- Feld s zählt nur bei f = 2 und wird sonst ignoriert.
- Befund am Korpus: f = 0 bei 319 Flächen, 209 davon mit Werten wie 26,39798646893; f = 1 bei 115 Flächen, bis auf eine mit runden Werten; f = 2 bei 31 Flächen, immer eine fixierte Quelle mit gleichem Wert. ray-optics liest das Feld als Aperturtyp, das passt nicht zum Korpus.
- `DIAM` allein erzeugt keine Apertur, außer an der Blende. Ob ein fixierter Halbdurchmesser ohne `CLAP` oder `FLAP` in OpticStudio vignettiert, ist ungeprüft. Im Korpus hängt keine Datei davon ab (zwei Fälle: eine Blende, eine Bildfläche mit `DIAM 0`).

**Apertur einer Fläche** (eine Fläche hat genau eine Apertur):
- `CLAP rmin rmax` → `CircularAperture{rmax, rmin}`.
- `FLAP x rmax …` bei f = 1 oder 2 → `CircularAperture{rmax}`.
  - Im Korpus 143 Mal, nur bei f = 1 oder 2, immer x = 0 und rmax = v.
  - optiland liest rmax aus dem zweiten Feld und setzt den Innenradius 0 (`_read_floating_aperture`). Die Bedeutung des ersten Felds belegt kein Leser; x ≠ 0 ist deshalb `zmx.aperture_unsupported`.
  - [UG] „Aperture Type“ stützt das für die Blende bei Float By Stop Size: „the Solve Type of Clear Semi-Diameter on the STOP surface will be forced to Fixed. If the surface is a dummy surface, the Surface Aperture will be set to None. If the surface is not a dummy surface, the Surface Aperture will be set to Floating Aperture.“
- `FLAP` bei f = 0 entfällt mit der Warnung `zmx.aperture_dropped`. Auf 15 gedruckten Stellen würde sie real gezielte Randstrahlen knapp beschneiden, obwohl sie nach Konstruktion alle Strahlen durchlässt. Im Korpus kommt das nicht vor.
- `CLAP` und `FLAP` an derselben Fläche → `zmx.aperture_conflict`.
- rmax = 0 (`CLAP`, `FLAP`) oder rmax ≤ rmin (`CLAP`) → `zmx.aperture_invalid`.
- `OBDC` ≠ 0 (Dezentrierung der Apertur) → `zmx.aperture_decenter`.
- `SQAP`, `ELAP`, `OBSC` kommen in PR C; bis dahin `zmx.aperture_unsupported`.

**Blende (`STOP`):**
- **Ebene Luft-Luft-Fläche** (im Korpus 33 von 54) → `stop`-Element. Eine gekrümmte Luft-Luft-Fläche wird ein `stop`-Element mit ihrer Form.
- **Linsen- oder Spiegelfläche** (im Korpus 19 bzw. 2) → `aperture.stop` = ID der Fläche nach ADR 0039. Das Ereignis der Fläche behält seine Art.
- **Radius der Blende**, in dieser Reihenfolge:
  1. Trägt die Fläche ein `CLAP` oder ein gültiges `FLAP`, gibt dessen rmax den Radius genau vor. Bei `FLOA` muss rmax = v sein, sonst `zmx.stop_radius_conflict`.
  2. Sonst bei `FLOA` oder bei f = 1 oder 2: genau v.
  3. Sonst, bei `ENPD`/`FNUM`/`OBNA` mit f = 0: 1,1 · v. Das gilt auch, wenn ein `FLAP` nach der Regel oben entfallen ist.
- **Zur dritten Regel:** Bei `ENPD`/`FNUM`/`OBNA` bestimmt die Aperturangabe die Pupille, nicht der Blendenradius. Das automatische v ist dort nur die von Zemax gefundene Strahlhöhe; mit ausgeschalteter Strahlzielung (`RAIM`) gehört es sogar zu einer anderen Zielung als unserer. Mit 1,1 · v vignettiert kein real gezielter Randstrahl an der Blende, solange der paraxiale Blendenradius R_s aus der Aperturangabe ≤ 1,1 · v ist. Nach `compile` prüft der Import das; ist R_s > 1,1 · v, gibt es die Warnung `zmx.stop_radius_small` (keine Radiusrechnung, nur ein Vergleich). Gezielt wird auf den paraxialen Blendenradius aus der Aperturangabe (ADR 0039); die Regel aus #310 greift nur bei Zielen außerhalb des Rands.
- v = 0 an der Blende ohne `CLAP`/`FLAP` → `zmx.stop_radius_missing`.
- Ein rmin > 0 an der Blende wird eine zentrale Obskuration der Pupille (ADR 0032, Nachtrag #229). Im Korpus kommt das nicht vor.

### 9. Konfigurationen

- `MNUM n` mit n > 1 → `zmx.multi_config`. Das Modell hätte mit Parametertabelle und Konfigurationen (ADR 0029) die Struktur dafür; die Abbildung der Operanden ist ein eigenes Folge-Issue.
- Bei `MNUM 1`:
  - `THIC s 1 v` und `CRVT s 1 v` müssen den Daten von Fläche s entsprechen (DISZ bzw. CURV, bitgleich), sonst `zmx.config_mismatch`. Die Feldfolge Fläche, Konfiguration, Wert ist eine Lesart am Korpus; dort sind alle 10 `THIC`-Zeilen bei `MNUM 1` bitgleich zu DISZ.
  - `MOFF` wird übergangen.
  - Jeder andere Operand gibt einmal `zmx.keyword_ignored`.

### 10. Was nicht übernommen wird

- Variablen, Solves und Pickups: Die Datei enthält die aufgelösten Werte, diese werden übernommen.
- Merit-Funktion, Toleranzen, Coatings (`COAT`).
- Strahlzielung (`RAIM`). Unsere Zielung ist real; eine Datei mit ausgeschalteter Strahlzielung gibt deshalb andere Spots als OpticStudio. Im Korpus ist sie in 52 von 54 Dateien aus.
- Analyseeinstellungen, Polarisation (`POLS`), nichtsequenzielle Daten (`NSCD`).

### 11. Diagnosecodes

Neue Codes mit dem Erzeuger `zmx` in `rtt-diagnostics/codes.hpp` und `docs/diagnostics.md`. Das ändert den öffentlichen Header einer anderen Bibliothek; dieses ADR ist der Beschluss dafür (Regel 8), wie ADR 0040 für seine Codes.

- **Fehler (`ZmxError`):**
  - Datei: `zmx.parse`, `zmx.encoding_unsupported`, `zmx.mode_unsupported`, `zmx.unit_unsupported`, `zmx.environment_unsupported`;
  - Systemdaten: `zmx.aperture_unsupported`, `zmx.field_unsupported`, `zmx.vignetting_unsupported`, `zmx.multi_config`, `zmx.config_mismatch`;
  - Flächen und Elemente: `zmx.surface_unsupported`, `zmx.asphere_r2`, `zmx.object_medium_infinite`, `zmx.object_medium_unsupported`, `zmx.mirror_in_glass`, `zmx.image_in_glass`;
  - Gläser: `zmx.glass_unknown`, `zmx.model_glass`;
  - Aperturen und Blende: `zmx.aperture_conflict`, `zmx.aperture_invalid`, `zmx.aperture_decenter`, `zmx.stop_radius_missing`, `zmx.stop_radius_conflict`;

- **Warnungen:** `zmx.keyword_ignored`, `zmx.surface_dropped`, `zmx.aperture_dropped`, `zmx.glass_reference_temperature`, `zmx.afocal_image_space`, `zmx.stop_radius_small`.

Die Checkliste „Neuer Flächentyp“ (ADR 0041) gilt für I1 nicht: kein neuer Typ, kein Schemasprung.

### 12. Abnahme

**Repo-Tests** mit kleinen, handgeschriebenen ZMX-Dateien. Gläser aus `tests/catalogs/schott.agf` (N-BK7, F2) und `tests/catalogs/m2/schott.agf` (N-LAK9, N-SF5), alle mit T_ref = 20 °C.

1. **Struktur gegen Solldateien** unter `tests/reference/m8/zmx/`, unabhängig vom Import erzeugt.
   - Ein Python-Skript im Testordner rechnet R = 1/c in double und λ_vac mit einem eigenen Ciddor nach der Quelle (NIST, Gl. (A21)–(A41)), nicht mit unserem Code. Daraus schreibt es die Solldatei.
   - Verglichen werden Elemente, Namen, IDs, Materialien und Posen. Beide Dateien werden eingelesen, die Zahlen als double verglichen, nicht die Bytes. nlohmann schreibt mit Grisu2, das ist nicht immer die kürzeste Form.
   - **Dateien in mm:** jede Zahl bitgleich außer den Wellenlängen, `image_fnumber` = v/n_Luft und `object_na` = n_Luft · v. Die Wege sind festgelegt: R = 1/c, α unverändert, Dickensummen von vorn nach hinten, 1,1 · v als ein Produkt; das Skript rechnet sie in derselben Reihenfolge.

   - **Andere Einheiten:** dieselben Wege wie Punkt 3, wenige ulp.
   - **`UNIT IN`/`METER` gegen die Solldatei in mm:** Die Toleranz folgt aus der Zahl der gedruckten Stellen, denn in Zoll gedruckte Werte treffen mal 25,4 nicht die mm-Werte.

2. **EFL, BFL, Spot-RMS** zwischen Import und Soll, beide mit unserem Code. Das prüft nur, dass die Abweichung bei den Wellenlängen nichts ausmacht. Die Grenze folgt aus ∂n/∂λ · Δλ.
3. **Unabhängige erste Ordnung:**
   - Das Skript rechnet EFL und BFL mit einem eigenen paraxialen y-nu-Trace (Greivenkamp, S. 9-2), mit Brechzahlen aus den AGF-Koeffizienten (Formeln nach [UG]) und eigenem Ciddor.
   - Es rechnet einmal absolut wie rtt und einmal relativ zu Luft (n_rel bei λ_Luft, Luft = 1). Damit prüft es `efl · n_Luft = EFL_rel` und `rear_focal_length = EFL_rel`, also die Regeln aus Punkt 4 für Luft → Vakuum. Dazu die Aperturen: Die EPD aus `image_fnumber` muss EFL_rel / F#_Zemax sein, und die paraxiale Randsteigung u = NA_rtt / n_abs,Objekt muss NA_Zemax / n_rel,Objekt sein (n_Luft kürzt sich); mit `reading = real` zusätzlich sin U = NA_Zemax / n_rel,Objekt bei λ_ref.

Etwa 10⁻¹⁴ relativ auf λ ändert n über dn/dλ nur um etwa 10⁻¹⁶. Ein y-nu-Trace über N Flächen rundet je Schritt mit wenigen ε; mit N ≤ 20 und Reserve ist die Grenze deshalb 10⁻¹² relativ, multipliziert mit der Kondition Σ|y_i φ_i| / |y_1 Φ| des Systems (sie wächst bei Teleobjektiven und fast afokalen Systemen). `efl · n_Luft = EFL_rel` gilt nur, wenn jeder Katalog T_ref = 20 °C hat; das Skript prüft das vorher.

Abnahme 3 prüft die Umsetzung, nicht die Deutung. Die Deutung bleibt unbestätigt, bis der Maintainer sie in OpticStudio prüft.

## Verworfen

- **nd/νd der `GLAS`-Zeile als Wächter oder zur Auswahl** (optiland entscheidet damit bei Doppelten): Im Korpus passen die Werte fast nie zum Glas (Punkt 7).

- **Blendenradius aus unserer paraxialen Rechnung statt 1,1 · v:** mehr Code für denselben Zweck (Entscheidung zu Frage 3).
- **Wellenlängen ohne Umrechnung oder mit einem Schritt:** Die Abweichung von 10⁻⁹ relativ ist größer als jede andere Rundung des Imports.
- **Aluminium für `MIRROR`:** bräuchte ein Coating mit komplexem Index für jeden Spiegel. `ideal_mirror` ist die übliche Annahme im Optikdesign; die Abweichung steht in Punkt 5.
- **Leser unter GPL/LGPL als Quelle:** lizenzrechtlich ausgeschlossen (ADR 0010).
- **`object.reference` für den Objektabstand:** DISZ₀ bezieht sich auf Fläche 1, die als Dummy entfallen kann; mit dem Ursprung dort geht DISZ₀ bitgleich durch.

## Nachtrag (#317, PR C, 2026-11-07): Koordinatensprünge, gekippte Ebenen, ideale Linse, Aperturen

- **Vorschlag und Entscheidung:** Vorschlag PR C auf #317 (Kommentar 6711992341), vom physik-reviewer in drei Durchgängen geprüft; der Maintainer ist allen Empfehlungen zu F1 bis F7 gefolgt (Kommentar 6712015517). Folge-Issues: #357 (paraxiales Modell gefalteter Pfade), #358 (gekippte Objektebene, nach 1.0).
- **Quellen:** [UG] zusätzlich „Tilted“, „Paraxial“, „Surface Tilt/Decenter Tab“, „Aperture surface properties“, „Aperture Type Codes and Parameters“, „Surface Apertures“; [ZR] `COORDBRK` und `PARAXIAL` (ray-optics), `TILTSURF` (CEO), `SQAP`/`ELAP` (optiland). Die Herleitungen unten stehen in `docs/quellen.md` als „hergeleitet in #317“.
- **Rahmen:** Der Import führt den Rahmen von OpticStudio mit (Ursprung im Scheitel von Fläche 1). Eine Fläche liegt im Rahmen, ihre Dicke verschiebt ihn längs des lokalen z, ein Spiegel dreht ihn nicht ([UG] „Thickness“, ADR 0028, Punkt 4).
- **Koordinatensprung** ([UG] „Coordinate Break“): Flag 0 = R = Rx(a)·Ry(b)·Rz(c) nach der Dezentrierung (dx, dy), Flag ≠ 0 = Rz(c)·Ry(b)·Rx(a) vor ihr; die Dicke zuletzt. Er ist keine Fläche, sondern ein Schritt zur nächsten; er übernimmt das Medium der Fläche davor. Posen, in dieser Reihenfolge:
  1. Ein Sprung ohne Dezentrierung und Kippung ist eine reine Dicke.
  2. Genau ein verbleibender Sprung mit Flag 0, oder mit Flag ≠ 0 und höchstens einer Kippung: `rotate_first` mit den Winkeln der Datei; Flag 0 Pivot (dx, dy, t₁), Flag ≠ 0 Pivot (0, 0, t₁), `position` (dx, dy, t₁ + t₂). Das gilt auch für das erste Element (absolut).
  3. Sonst wird die Transformation von der letzten Fläche zur nächsten ausmultipliziert und als `translate_first` mit der Zerlegung R = Rx(a)·Ry(b)·Rz(c) geschrieben (b = atan2(R₀₂, hypot(R₀₀, R₀₁)), a = atan2(−R₁₂, R₂₂), c = atan2(cos a·R₁₀ + sin a·R₂₀, cos a·R₁₁ + sin a·R₂₁)). Nahe der Einheit stehen dann Winkel um 10⁻¹⁵° in der Datei.
- **Gekippte Ebene** ([UG] „Tilted“): Ebene mit R = Rx(α)·Ry(β), α = atan(tan θy), β = −atan(tan θx cos α), auf der Flächenpose (bei der ersten Fläche eines Elements absolut, bei einer inneren Linsenfläche in der relativen Pose). Weil der Rahmen bleibt, nimmt die nächste Fläche die Drehung wieder heraus: ohne Sprung dazwischen `rotate_first` um den Scheitel mit `position` (0, 0, t) und den Winkeln von Rᵀ, sonst Regel 3. Ohne Apertur zwischen Luft und Luft entfällt sie wie jede Ebene.
- **Ideale Linse** ([UG] „Paraxial“): `thin_element` mit Ebene und `ideal_lens` f·s, auch als Blende (`aperture.stop`). Nur mit Luft auf beiden Seiten; f = 0 ist eine Ebene. OPD-Modus 2 ist exakt; 0, 1 und 3 gehen ohne `object_distance` und geben `zmx.paraxial_opd`.
- **Aperturen:** `SQAP`/`ELAP` → `RectangularAperture`/`EllipticalAperture` mit den Halbbreiten mal s. An der Blende und auf einer gekippten Ebene sind sie (wie `CLAP`/`FLAP` dort) `zmx.aperture_unsupported`. **Abweichung von den Folgen oben:** `OBSC`, `SQOB` und `ELOB` kommen mit #320 (F3), nicht in PR C; sie bleiben `zmx.aperture_unsupported`.
- **Paraxial:** Nach `compile` ruft der Import einmal `first_order`. Lehnt es den Pfad ab (gefaltet, gekippt, dezentriert, auch ein gekippter Detektor), gibt es `zmx.paraxial_unavailable` statt `zmx.stop_radius_small`; das System wird importiert, Analysen mit paraxialer Zielung brauchen vorgegebene Startstrahlen (#357).
- **Gekippte Bildfläche:** gedrehter Detektor mit der Warnung `zmx.tilted_image`. Seine Bildkoordinaten liegen in der gekippten Ebene; OpticStudio projiziert sie auf den ungekippten Rahmen (bei tan θy = 1,21 um den Faktor 1,57 verschieden). Eine gekippte Objektfläche bleibt `zmx.surface_unsupported` (#358).
- **Schlüsselwörter in Flächenblöcken:** Ein unbekanntes Schlüsselwort dort ist jetzt der Fehler `zmx.keyword_unsupported`, denn es könnte die Optik ändern; das Schlüsselwort des Reiters „Surface Tilt/Decenter“ belegt kein Leser. Still bleiben die Liste aus Punkt 2 und neu `PPAR`, `PZUP`, `VPAR` (Pickup- und Variablenvermerke neben dem aufgelösten Wert), `TCED` (Lesart: Ausdehnungskoeffizient, nur thermisch), `SSID` (Flächennummer neuerer Dateien), `VDSZ` nur mit Nullen und `FIMP` nur ohne Wert (lokale Beispieldateien VERS 150514 bis 240823). Neuere Dateien können weitere Schlüsselwörter tragen; die stille Liste wächst dann mit Beleg. Außerhalb der Flächen bleibt es bei `zmx.keyword_ignored`.
- **Weitere Regeln:** `STOP` oder Apertur an einem Sprung → `zmx.coordbrk_surface`; Sprung an Objekt- oder Bildfläche, ideale Linse als Spiegel, Bildfläche oder mit `CURV` ≠ 0 → `zmx.surface_unsupported`; `GLAS` an einem Sprung nur mit dem Medium davor, sonst `zmx.parse`; bei Objektglas muss die erste Fläche, die kein Sprung ist, eine Linse beginnen. An einem Sprung werden `DIAM`, `CURV`, `CONI` und `PARM` ab 7 übergangen (im Korpus immer 0). Eine gekippte Ebene mit `CURV` ≠ 0 ist `zmx.surface_unsupported`. Der Test der Zerlegung prüft die Rahmen der Fläche dahinter auf 10⁻¹⁴ statt des Rückwegs der Winkel auf 2·10⁻¹⁵ (Vorschlag, Punkt 10.8); die Zerlegung ist intern.
- **Neue Codes:** Fehler `zmx.coordbrk_surface`, `zmx.paraxial_medium`, `zmx.keyword_unsupported`; Warnungen `zmx.paraxial_unavailable`, `zmx.paraxial_opd`, `zmx.tilted_image`. `rtt_io` linkt zusätzlich `rtt::paraxial`.
- **Abnahme:** Die gefalteten Fälle haben keine Solldatei; `make_zmx_cases.py` schreibt den Rahmen jeder Fläche nach [UG] in `frames.json` (Scheitel ≤ 10⁻¹² mm, Achsen ≤ 10⁻¹⁴). Äußere Anker: der Faltspiegel gegen `m6/fold45_focus` (Lagen, Normalen, Brennpunkt), die Parabel außer Achse gegen ihren Brennpunkt, die gekippte Bildfläche gegen z = x tan θx + y tan θy, Platte und Prisma gegen eine eigene Snellius-Rechnung. **Grenze:** Gekippte Linse und gekippte Ebenen prüft im Repo nur das eigene Skript, das die Lesart mit dem Import teilt; eine Bestätigung aus OpticStudio steht aus (Datei aus F6, wenn möglich).

## Nachtrag (#360, PR A, 2026-11-10): `ODDASPHE` und `TOROIDAL`

Vorschlag in #360; der Maintainer folgte allen Empfehlungen H1 bis H6 (2026-11-10, in der Sitzung). Belege in `docs/quellen.md`, Zeile „ZMX-Import: `ODDASPHE` und `TOROIDAL`“.

- **Umfang (H1, H6):**
  - PR A: `ODDASPHE` und `TOROIDAL`;
  - PR B: `BICONICX` und `QED_TYPE` mit dem Lesen der Zusatzdaten (`XDAT`); er schließt #360;
  - Zernike-Sag und XY-Polynom kommen nach S3 (#316).
- **`ODDASPHE`** ([UG] „Odd Asphere“, optiland) wird `odd_asphere` (ADR 0043):
  - c = `CURV`/s, k = `CONI`, A_n = β_n · s^(1−n) für `PARM` n = 1 … 8, Nullen am Ende abgeschnitten.
  - Bei c = 0 entfällt die Konik, denn sie wirkt dort nicht.
  - Ohne β ist die Fläche `conic` bzw. `plane` wie bei `STANDARD`.
  - Ein `PARM` außerhalb 1 bis 8 mit einem Wert ≠ 0 gibt `zmx.parse`.
- **`TOROIDAL`** ([UG] „Toroidal“, ray-optics) mit `PARM 1` = R (Drehradius, Länge) und `PARM 2` … 8 = α1 … α7:
  - **Abbildung:**
    - `CURV` ≠ 0, R ≠ 0: `toroid` (radius = 1/c, conic, A4 … A14 = α2 … α7, radius_of_rotation = R);
    - R = 0: `cylinder` mit demselben Profil.
  - **Lage der Drehachse:** bei z = +R. Das ist die Festlegung von ADR 0042, belegt durch `YToroid.sag` in ray-optics; [UG] nennt die Lage nicht.
  - **Fehler und Grenzfälle:**
    - α1 ≠ 0 gibt `zmx.asphere_r2`, denn das Modell hat den y²-Term nicht (ADR 0042, F2).
    - `PARM 0` (Extrapolationsflag der Zernike-Terme) wird übergangen.
    - **Zusatzdaten:** Die Zernike-Terme stehen in den Zusatzdaten ([UG]: Parameter 13 = Zahl der Terme, 14 = Normierungsradius, 15–245 = Koeffizienten), in der Datei `XDAT 1`, `XDAT 2`, … OpticStudio schreibt `XDAT 1` und `XDAT 2` auch ohne Terme (Testdatei `HoO-V2C18Ex46.zmx` von ray-optics, Review von PR A). Mit 0 Termen werden sie übergangen, mit Termen gibt es `zmx.surface_unsupported`. `XDAT` an einem anderen Typ bleibt `zmx.keyword_unsupported` (bis PR B für `QED_TYPE`).
    - Ein `PARM` über 8 mit einem Wert ≠ 0 gibt `zmx.parse`.
  - **Abweichung von optiland:** optiland liest alle Parameter des Toroids eine Stelle später; der Import folgt [UG] und ray-optics.
- **Brechkraft nur in x (H2):** `TOROIDAL` mit `CURV` = 0 und R ≠ 0 wird ein `cylinder` vom Radius R, der Rahmen der Fläche um +90° um z gedreht (lokales x = globales y).
  - **Bildfläche:** Als Bildfläche ist das `zmx.surface_unsupported`, denn der gedrehte Rahmen des Detektors drehte die Bildkoordinaten um 90° (Review von PR A).
  - **Rahmen:** Die gedrehte Fläche wird wie eine gekippte Ebene platziert (Nachtrag PR C, Punkt 3): Die nächste Fläche liegt wieder im ungedrehten Rahmen.
  - **Aperturen:** Rechteck und Ellipse tauschen ihre Halbbreiten, denn OpticStudio prüft sie im ungedrehten Rahmen.
  - **Fehler:** Mit Termen in y (α ≠ 0) ist das weder Zylinder noch Toroid: `zmx.surface_unsupported`. `CURV` = 0 und R = 0 ohne Terme ist eine Ebene.
- **Paraxial:** `odd_asphere` hat die Scheitelkrümmung c + 2 β2 (ADR 0041); mit β1 ≠ 0 gibt es kein paraxiales Modell und die Warnung `zmx.paraxial_unavailable`, ebenso bei Toroid und Zylinder (nicht rotationssymmetrisch); `first_order_section` geht.
- **Abnahme:**
  - **Solldateien:** Die Fälle `oddasph`, `oddasph_in`, `oddasph_cone`, `toroid` und `toroid_in` kommen mit Solldatei aus `make_zmx_cases.py` (bitgleich, Wellenlängen auf 10⁻¹⁴).
  - **Erste Ordnung:** gegen einen eigenen y-nu-Trace. Bei der Odd Asphere rotationssymmetrisch, beim Toroid je Schnitt (x–z mit 1/R, y–z mit c), ebenso beim gedrehten Zylinder (`xcylinder`, ohne Solldatei, weil die Pose der Rückdrehung rundet).
  - **Inhaltswächter:** Alle Strahlen kommen an, und drei Felder geben drei verschiedene Bildschwerpunkte.
- **Regel 2:** Der Fehlerfall in `test_zmx.cpp`, der `TYPE TOROIDAL` als Beispiel für `zmx.surface_unsupported` nahm, nimmt jetzt `TYPE SZERNSAG` (Freigabe des Maintainers, 2026-11-10).
- **Export (H5):** Der ZMX-Export schreibt `ODDASPHE` noch nicht (ADR 0045, Punkt 4); das kommt in ein eigenes Folge-Issue.
