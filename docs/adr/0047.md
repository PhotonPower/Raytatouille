# ADR 0047: macOS 26 (arm64) als dritte Plattform

**Status:** angenommen (Maintainer, 2026-11-11, #373); ersetzt in ADR 0011 den Punkt „Verworfen: macOS“.

## Kontext

ADR 0011 legte Linux und Windows als Plattformen fest und verwarf macOS ohne Begründung. Ein
Testbuild auf macOS 26.4 (Apple-Silicon, Apple clang 21, libc++, Abhängigkeiten aus Homebrew,
`-Werror`) in #373 zeigt, was dafür nötig war:

| Befund | Lösung | Stelle |
| --- | --- | --- |
| `std::from_chars` für `double` gibt es in Apples libc++ erst ab macOS 26 (`'from_chars' is unavailable: introduced in macOS 26.0`); genutzt u. a. in `rtt-io/src/numbers.hpp`, `rtt-material`, `rtt-model` | Mindestversion macOS 26 (Punkt 1) | dieses ADR |
| libc++ rechnet `std::sqrt(std::complex)` über die Polarform; bei Totalreflexion Re q ≈ 10⁻¹⁷ statt 0, die ideale Beschichtung erkannte die Totalreflexion nicht (7 Tests rot) | `rtt::math::principal_sqrt` | ADR 0046, #374 |
| libc++ hat die mathematischen Spezialfunktionen aus C++17 nicht (`std::cyl_bessel_j`) | `rtt::math::bessel_j0`, `bessel_j1` mit Schalter über das Feature-Makro | ADR 0033, Nachtrag #373, #375 |
| Clang fasst auf arm64 `a * b + c` zu FMA zusammen (4 Tests rot, u. a. exakte Symmetrie der Pupillenzellen) | `-ffp-contract=off` für alle Ziele | ADR 0029, Nachtrag #373, #376 |

Danach ist der Build ohne Behelf grün: 1578 von 1578 C++-Tests und 1475 Python-Tests
einschließlich der Bitvergleiche mit C++, keiner übersprungen. Entscheidung des Maintainers in
#373: Mindestversion 26, keine gelockerten Toleranzen.

## Entscheidung

1. **macOS ab Version 26 auf arm64 (Apple Silicon)** ist unterstützte Plattform, mit Apple clang
   aus Xcode bzw. den Command Line Tools und libc++.
   - **Mindestversion 26.0:** Darunter fehlt `std::from_chars` für `double` in der libc++ des
     Systems. Ein eigener Ersatz (etwa `fast_float`) wäre eine neue Abhängigkeit (ADR 0010) für
     Systeme, die Apple nicht mehr mit Sicherheitsupdates versorgt.
   - Die Wurzel-`CMakeLists.txt` setzt `CMAKE_OSX_DEPLOYMENT_TARGET` vor `project()` auf 26.0, wenn
     weder die Variable noch `MACOSX_DEPLOYMENT_TARGET` in der Umgebung gesetzt ist. Ein kleinerer
     Wert ist ein Fehler beim Konfigurieren mit einer klaren Meldung, statt eines Fehlers beim
     Übersetzen tief in `rtt-io`.
   - **Python-Wheels** tragen damit das Tag `macosx_26_0_arm64`. Mit einem Python, das ältere
     Versionen anpeilt (z. B. von python.org: macOS 11), ist `MACOSX_DEPLOYMENT_TARGET=26.0` zu
     setzen; die Fehlermeldung sagt das.
   - **Intel-Macs (x86-64)** sind nicht getestet und nicht zugesagt. macOS 26 ist die letzte
     Version für Intel-Macs.
2. **Presets und CI:**
   - Neue Presets `ci-macos-clang` (Release, `-Werror`, vcpkg, Mindestversion 26.0) und
     `ci-macos-python`.
   - Neuer CI-Job auf dem Runner `macos-26` (arm64); der Runner muss selbst macOS 26 sein, sonst
     laufen die Tests nicht. Ein Eintrag in der Python-Matrix mit Python 3.13, `pip install .` und
     der Prüfung der Editable-Installation (#271).
   - Lokal genügen Homebrew-Pakete mit dem Preset `dev` (AGENTS.md, README).
3. **Bitgleichheit** wie ADR 0011: je Plattform und Compiler, nicht plattformübergreifend. Durch
   ADR 0029, Nachtrag #373, rechnen die Grundrechenarten auf arm64 wie auf x86-64; Unterschiede
   bleiben in libm-Funktionen (`sin`, `cos`, `j0`, …).
4. **Neue Regel für portablen Code**, die Fehlerklassen aus #373:
   - komplexe Wurzeln über `math::principal_sqrt`, nicht `std::sqrt` (ADR 0046, Punkt 5);
   - keine mathematischen Spezialfunktionen aus `<cmath>` direkt, sondern über `rtt-math`;
   - keine Abhängigkeit von FMA-Kontraktion.
5. **Linker:** Auf macOS unterdrückt `-no_warn_duplicate_libraries` die Warnung von Apples Linker
   über statische Bibliotheken, die CMake für die Reihenfolge doppelt auf die Kommandozeile setzt.
   Das ist nur Rauschen, kein Fehler.

## Verworfen

- **Mindestversion unter 26 mit Ersatz für `from_chars`:** neue Abhängigkeit für veraltete
  Systeme; Entscheidung des Maintainers.
- **Toleranzen lockern, damit libc++ und FMA durchgehen:** verdeckt echte Fehler (ADR 0046) und
  die exakte Symmetrie (ADR 0029, Nachtrag #373).
- **GCC aus Homebrew als Compiler für macOS:** Apple clang ist der Systemcompiler, und die libc++
  des Systems ist der Fall, den Nutzer haben. GCC mit libstdc++ übersetzt den Code ebenfalls (in
  #373 für `psf.cpp` und `bessel.hpp` geprüft), wird aber nicht in der CI getestet.

## Folgen

- Plattformen: Linux, Windows, macOS 26 (arm64). AGENTS.md, README und `docs/architecture.md`
  nennen alle drei; die Definition of Done verlangt auch den macOS-Job grün.
- Ein vierter vcpkg-Cache in der CI (`arm64-osx`); der erste Lauf baut die Abhängigkeiten.
